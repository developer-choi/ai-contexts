## 골격은 사례집에서 고른다

article은 골격이 곧 글의 성패다. 헤딩을 세우기 전에 [article-skeletons.md](../../../contexts/writing-guide/article-skeletons.md)에서 이번 글의 상황에 맞는 서사구조를 고른다.

## 안내 문구

"이 글을 읽을 독자가 지금 어떤 방법을 쓰고 있을 것 같은지, 그리고 도달시키고 싶은 방법이 무엇인지 알려줘. 끝까지 끌고 갈 예시 하나도 함께."

## 필수 요소

- 하나의 예시를 전 절이 공유한다. 절마다 예시가 바뀌면 독자가 차이를 잴 기준을 잃는다.
- 각 단계 절은 같은 형식으로 닫는다 (「얻는 것과 잃는 것」).
- 코드 블록은 실행 가능한 최소 단위로. 생략은 `...`이 아니라 주석으로 무엇이 생략됐는지 밝힌다.

## 외부 근거 인용 배치

- 본문에는 한국어 주장만 쓴다. 영어 원문을 문단 사이에 끼우면 독자가 주장을 따라가던 흐름이 끊긴다.
- 영어 원문은 글 맨 끝에 출처별로 모은다. 헤딩은 `## References: [문서 제목](URL)`.
- 각 References 절 안은 `> 영어 원문` 인용블록 다음에 `- 한국어 해설` 불릿.
- 출처가 여럿이면 References 절을 출처 수만큼 나란히 둔다. 하나로 합치면 독자가 어느 문서의 말인지 잃는다.

## length_target default

각 단계 + 오답 사례 + 결론 = 약 1500-2500단어. frontmatter `length_target` 명시 시 우선.
