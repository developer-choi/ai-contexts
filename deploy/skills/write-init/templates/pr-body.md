# pr-body 재료

본문에 옮겨 펼 골격이 아니라, PR 본문이 다루는 재료 목록이다. 이 파일의 제목·절 이름은 본문에 넣지 않는다.

## 안내 문구 매핑

| subtype | 안내 |
|---------|------|
| (없음, 일반 PR) | "리뷰어가 알아야 할 핵심 결정 적어줘" |
| recruitment | "너가 가장 어필하고 싶은 부분 적어줘" |

## PR 제목

패키지 본문의 H1이 PR 제목이다. 게시할 때 H1은 PR 제목 칸에, frontmatter와 H1을 뺀 나머지는 PR 본문에 넣는다.

제목은 합의한 `key_message`를 한 줄 길이로 줄이거나 늘려 짓는다. 줄일 때는 `key_message`의 주장을 남기고, 그 주장을 받치는 방법·근거부터 덜어낸다.

- 확인한 결과가 있으면 결과까지 담는다. 「~하는지 확인 완료」처럼 한 일만 적지 않고 「~할 수 있음을 확인」처럼 드러난 것을 적는다
- 명사형 보고체(「~확인」·「~추가」·「~제거」)로 끝낸다
- 끝에 마침표를 찍지 않는다
- `feat:` 같은 conventional commit 접두사를 붙이지 않는다
- 공백 포함 60자 이하

## 재료

절은 주제마다 하나씩 세운다. 주제는 이 PR에서 내린 결정 하나, 또는 만든 동작 하나다. 절 제목은 그 주제가 말하는 내용으로 짓는다. 아래 재료 이름이나 「배경」·「요약」처럼 어느 PR에나 붙는 이름은 제목으로 쓰지 않는다.

한 절 안에서 그 주제에 있는 재료만 쓴다. 모든 재료가 다 있어야 하는 것은 아니다.

- **왜 필요했나** — 이 주제를 다루게 된 문제·요구사항·배경. 메인이 이슈·계획 문서·대화에서 추출
- **무엇을 골랐고 왜** — 검토한 후보, 고른 기준, 판정. 메인이 결정 기록·대화에서 추출
- **어떻게 동작하나** — 구현 방식과 실제 동작, 필요하면 코드 조각. 메인이 git diff·코드에서 추출

커밋 목록이나 바꾼 파일·컴포넌트를 나열한 요약은 넣지 않는다 — GitHub PR 화면이 커밋과 파일 변경을 이미 보여준다.

## subtype별 length_target default

| subtype | default |
|---------|---------|
| (없음, 일반 PR) | 짧게: 1-2 섹션, 합쳐서 3-5문단 (약 200-400단어) |
| recruitment | 주요 섹션 3-4개, 섹션당 3-4문단 (약 200-300단어), 표·이미지·commit 링크 활용. 의사결정 섹션은 30-50% 더 길게 |

frontmatter `length_target`이 명시되면 그쪽 우선. 없으면 위 default 적용.
