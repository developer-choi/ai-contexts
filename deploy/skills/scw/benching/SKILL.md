## 목적

벤치·eval을 돌려 스킬·규칙의 효과를 검증한다.

## 0건 수렴까지 재벤치

벤치 라운드에서 잔류 이슈가 1건이라도 남으면 다음 라운드로 넘어간다. 사용자가 명시적으로 "이 정도면 됐다"·"여기서 멈추자"고 말하기 전에는 자체 판단으로 라운드를 종료하지 않는다. 사용자가 매번 "더 돌려"라고 시키지 않아도 0건 수렴까지 자동 진행한다.

- 다음 라운드는 **같은 시나리오로** 재측정한다. 시나리오를 바꾸면 0건이 보강 효과인지 압박이 약해진 것인지 안 갈린다.
- 보강 변경은 라운드별 커밋으로 분리해 사용자가 diff로 라운드별 효과를 검토할 수 있게 한다.
- 반복 상한은 글로벌 규칙 「검증은 수렴할 때까지 반복」을 따른다.
- "97% 통과면 충분하다"·"잔류 1건은 자연 표현이라 어쩔 수 없다" 같은 자체 만족 종료 금지. 잔류 1건이 다음 사용 때 같은 누설로 재발하면서 가이드 신뢰도가 무너진다.
- 적용 범위: [의심 지점 개선 루프](../rounds/reviewing.md#의심-지점-개선-루프), [기능테스트](kinds/function-test.md)에서 벤치를 돌린 모든 경우.

### 물을 사람이 없을 때

먼저 사용자가 이 대화에 있는지 본다. 사용자가 대화에 있어 답을 받을 수 있으면 회차가 몇 번째든 이 갈래가 아니고 위 절을 따른다. 받은 지시에 사용자에게 되물을 수단이 없다고 적혀 있거나, 사용자에게 묻는 도구가 없는 서브에이전트로 돌고 있을 때만 이 갈래로 간다. 이 갈래는 위의 "자체 판단으로 라운드를 종료하지 않는다"와 전역 반복 상한보다 먼저 적용된다.

- 이 갈래에서만, 문안을 고치고 같은 시나리오로 다시 재는 회차는 최대 4회다. 고치기 전의 첫 측정은 세지 않는다. 4회째 측정에도 잔류가 남으면 더 고치지 않고 멈춘다.
- 멈추면 회차별 시나리오 통과/전체 수치, 쓴 run 수, 마지막 문안이 몇 회차 것인지를 보고하고, 결과를 "통과"가 아니라 "상한에 닿아 멈춤, 잔류 있음"으로 적는다.
- [operations.md 「멈춤 간격」](operations.md#멈춤-간격)의 첫 발사 전 질문은 하지 않고 batch 사이에서도 멈추지 않는다. 그 질문이 막던 총량은 이 회차 상한이 막는다.

## Eval

- eval은 반드시 sonnet 모델로 실행한다. 이유: 스킬은 비용 효율적인 모델이 이해할 수 있는 수준으로 작성돼야 한다. opus에서만 동작하는 스킬은 실용적이지 않다.
- 예외: write-init·write-refine 스킬은 opus로 실행한다. 내용 풍부화와 톤·구조·분량 판단이 핵심이라 sonnet 기준으로 작성하면 가치가 휘발한다.

## 비교 테스트는 AI가 수행

- 테스트 버전은 넉넉하게 만든다. OLD/NEW 2개에 한정하지 말고, 변형을 여러 개 만들어서 동시에 비교해도 된다 (예: OLD/NEW/NEW2/NEW3). 동시에 20개 미만으로
- "테스트 필요 없어 보인다"고 AI가 스스로 판단해 벤치를 스킵하지 않는다 — 벤치 면제는 사용자 즉석 리뷰로만 결정된다. 벤치로 넘어온 how는 어떤 것이든 테스트할 거리를 찾아내서 검증한다

## gotchas

- **벤치마크 인프라 실패 시 스킵 금지**: OLD 스냅샷 경로 오류 등으로 비교 대상이 무효화되면, 원인을 수정하고 해당 run만 재실행한다. "additive 변경이라 괜찮다"는 합리화로 넘어가지 않는다.
