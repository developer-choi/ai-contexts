# 읽었는데 안 쓴 문서 쌓기

문서가 잘못 놓였다는 것은 **그 문서를 연 세션만 안다.** 나중에 파일을 아무리 뜯어봐도 "그날 이게 쓰였나"는 안 나오므로, 세션이 닫힐 때 안 남기면 그 신호는 사라진다.

여기서 하는 일은 **기록**이라, 문제가 없던 세션에서도 돈다. 한 세션에서 안 쓰인 문서는 어느 세션에나 있어서 그것만으로는 자리가 틀렸다는 뜻이 안 된다. 같은 진입점에서 여러 세션에 걸쳐 거듭 안 쓰여 누계가 선을 넘은 문서만 회고에 올린다(아래 「선을 넘은 것」).

## 목록을 뽑는다

```
node {{skill_dir}}/scripts/session-state.mjs read-files --session <session_id>
```

기억으로 목록을 만들지 않는다 — 떠올려 적으면 인상에 남은 몇 개만 올라오고, 조용한 문서일수록 빠진다. 조용한 문서가 바로 찾으려는 대상이다.

이 목록은 `Read`와 셸 읽기 명령으로 연 문서만 센다. `Grep`으로 줄만 본 것과 훅이 붙여준 문서는 빠지지만, 빠지는 쪽이라 없는 신호를 만들지는 않는다.

## 두 칸을 채운다

스크립트가 낸 줄마다 **진입점**과 **사용 여부**를 붙인다. 무엇을 어떤 문장으로 판정하는지는 `read-files` 출력에 있다. 같은 문서를 두 진입점이 물었으면 줄을 나눈다.

## 누계에 더한다

판정을 `{ "<진입점>\t<경로>": "used" | "unused" | "excluded" }` 꼴 json으로 적어 넘긴다.

```
node {{skill_dir}}/scripts/session-state.mjs read-usage --session <session_id> --from <판정 json>
```

누계 파일의 자리·형식·세는 법은 이 스크립트가 소유한다 — 손으로 더하면 한 칸 잘못 세도 그 자리에서는 아무 일도 안 일어나고, 몇 달 뒤 안 차는 누계 횟수로만 드러난다.

`excluded`는 사용자가 「안 고친다」를 고른 것이다. 한 번 넣으면 다시 안 뜬다 — 없으면 같은 경고가 매 세션 반복되어 장치가 무뎌진다.

커밋은 회고의 다른 변경과 섞지 않는다 — 매 세션 붙는 기계적 갱신이라, 섞이면 회고 diff가 매번 지저분해진다.

## 선을 넘은 것

스크립트가 `[배치 의심]`을 내면 그 줄마다 회고 문제 목록에 올린다. 이번 세션이 그 문서를 연 이유와, 이 진입점이 그 문서를 언제 물어야 하는지를 함께 적는다. 누계는 여러 세션의 것이라 이번 세션 하나의 사정으로 「필요 없다」고 결론내지 않는다 — 가끔만 필요한 문서를 통째로 떼면 그 경우를 놓친다.

사용자에게 둘 중 하나를 고르게 한다.

- **고친다** — 여는 조건을 좁히거나 자리를 옮기는 백로그 항목으로 낸다
- **안 고친다** — 그 줄을 `excluded`로 적어 「누계에 더한다」의 명령에 다시 넘긴다
