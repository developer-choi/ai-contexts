# Pre-exit

세션이 끝날 때 그 세션을 돌아보는 스킬입니다.

## 동기

같은 실수를 두 번 하고 싶지 않았습니다.

AI와 작업하다 보면 방향을 수정하거나, 잘못된 결과물을 반려하는 일이 생깁니다. 이런 경험을 그냥 넘기면 다음 세션에서 같은 일이 반복됩니다.

세션이 끝날 때마다 무엇이 잘못됐는지, 어디에 규칙으로 남겨야 하는지를 정리하면 다음 세션부터는 같은 지적을 하지 않아도 됩니다.

이 회고 과정 자체를 프롬프트로 만들었습니다.

## 회고에서 하는 일

- 대화가 길어지면 앞부분이 요약으로 줄어드는데, 그 전에 따로 남겨둔 기록에서 당시의 지적을 다시 꺼내옵니다
- 이번 세션에 사용자가 한 말을 하나도 빼지 않고 번호 붙여 뽑고, 말마다 그것을 어떻게 처리했는지를 나란히 적습니다. 기억으로 세면 빠지는 것이 생기기 때문입니다
- 말에는 안 나타나지만 결과를 보면 드러나는 것도 함께 봅니다 — AI가 반대했는데 최종본이 사용자 말대로 간 자리, 검수를 통과하고도 계속 반려된 산출물, 같은 지적이 두 번 온 자리
- 반복된 실수 패턴을 찾아 어느 규칙 문서에 적어둘지 제안합니다. 자동 검사 도구로 걸러낼 수 있는 문제면 규칙 대신 도구 설정을 고치자고 제안합니다
- 이번 세션에서 규칙을 어겼거나 규칙대로 했다가 반려당했으면, 그 규칙이 이제는 없어도 되는 것 아닌지 함께 살펴봅니다. 규칙이 늘기만 하고 줄지 않으면 결국 아무도 읽지 않게 되기 때문입니다
- 사용자가 반려하거나 고친 것은 규칙 문장과 함께, 잘못된 예와 고친 예를 나란히 쌓아둡니다
- AI가 제안했지만 사용자가 다르게 판단한 것은 실수와 구분해 따로 모읍니다. 다음에도 반복될 취향이면 규칙으로 남기고, 그 세션에만 해당하는 사정이었으면 남기지 않습니다
- 같은 일을 다시 시키게 된 원인이 요청하는 쪽에 있었으면 무엇이 빠져 있었는지 사용자에게 짚어줍니다
- 세션에서 얻은 교훈은 그것이 활용될 맥락에 직접 심어둡니다. 컨벤션이면 컨벤션에, 워크플로우 개선이면 스킬에. 사람이 기억할 필요 없이 AI가 해당 맥락에서 자동으로 꺼내 씁니다
- 커밋되지 않은 변경사항을 확인합니다
- 이번 세션에서만 쓰려고 따로 만든 작업 폴더가 남아 있으면 정리합니다
- 이번 세션에서 자료를 보려고 연 브라우저 탭이 남아 있으면 닫습니다. 사용자가 직접 열어둔 탭은 건드리지 않습니다

## 세션 종류별 보강 회고

세션 종류에 따라 추가로 챙길 회고 항목이 있으면 따로 모아 둡니다. 그 종류의 작업을 한 세션이면 기본 회고에 해당 항목을 얹어 함께 정리합니다.

## 팀 에이전트 통합

세션에서 띄운 팀 에이전트·서브에이전트가 있으면, 회고를 시작할 때 각 에이전트에게도 회고를 요청해 결과를 받아옵니다. 각 에이전트가 자기 쪽에서 본 문제를 메인 회고와 함께 다루기 위해서입니다.
