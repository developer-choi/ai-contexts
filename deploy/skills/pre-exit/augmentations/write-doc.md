# write-doc 세션 보강

세션에서 `/write-doc`을 사용한 경우의 추가 회고. pre-exit 본 절차와 **함께** 수행한다 (대체 X, 추가 ○).

채점기가 숫자와 기계 매칭 위반을 띄우고, 사람은 반려와 다듬기 판단의 품질을 회수해 writing-guide·write-doc으로 돌려보낸다.

## 회고 대상 1: 채점

```
node {{skill_dir}}/../write-doc/scripts/score.mjs <산출물.md> [--props 명제리스트.txt] [--tokens N] [--turns N]
```

- 다듬기 검수에서 이미 채점했어도 다시 돌린다. 분량·핵심 명제·토큰·턴은 여기서만 낸다.
- `--tokens`·`--turns`는 세션에서 얻은 누적치를 넘긴다.
- 기계 매칭은 한국어 단어 경계가 없어 오탐이 난다(`유사` in `유사성`). 출력된 줄을 눈으로 보고 실제 위반만 회수한다.

## 회고 대상 2: 쌓이지 않은 반려

이번 세션의 반려(패키지 `rejected`, 사용자가 말로 고친 것, 사용자가 직접 고친 자리) 중 write-doc 마무리의 반려 적재가 다루지 않은 것만 사용자에게 보여 준다. 반려 적재에서 승인받은 것을 다시 내면 같은 교정을 두 번 승인하게 된다.

각 반려를 `{원본 → 수정 → 드러난 톤 선호}` 한 줄로 정리한다.

## 회고 대상 3: 다듬기 판단 점검

채점기가 못 잡는 판단 품질이라 사람이 회수한다.

- **리뷰어가 잡은 결함** — 검수가 `block`으로 짚어 고쳐진 표현 위반. 반복 유형이면 규칙·반려 표현으로 굳힐 후보.
- **아무도 못 잡은 결함** — 사용자가 뒤늦게 짚은 위반(채점기·리뷰어 둘 다 못 잡음). 새 규칙·반려 표현·채점기 보강 1순위.
- **과교정** — 멀쩡한 표현을 위반으로 오판해 고쳤다가 사용자가 되돌린 것. 규칙이 과하게 넓거나 리뷰어가 고확신 기준을 낮게 잡았다는 신호다. 결함을 찾으라고 세운 리뷰어는 멀쩡한 표현까지 깎아 본문을 밋밋하게 만드는 쪽으로 실패하므로 매 회차 본다.
- **사용자의 말을 문 지적** — 사용자가 직접 쓰거나 불러넣은 구절을 리뷰어가 반려한 것. 그 구절을 frontmatter `user_phrases`에 안 올렸다는 신호다.
- **출발점 오판** — 사용자가 들고 온 재료(구상·메모·초안·예전 글)를 잘못 읽어 초안을 두고 새로 쓰는 등 엉뚱한 데서 시작한 것. 무엇을 들고 왔는지 묻는 질문이 모호했는지 점검.

## 회고하지 않는 것

- **사실 오류 수정.** 다듬기는 표현만 다룬다. 사실 교정은 초안 단계 책임이라 규칙화 대상이 아니다.
- **그 문서 한정 일회성 표현 선택.** 반복될 톤 선호만 규칙화한다.

## 반영 위치

회수한 것은 백로그 항목으로 내고, 넣을 자리를 아래로 가른다. 채점 위반·반려·점검 결과가 모두 0건이면 "write-doc 채점·반려 없음"으로 보고하고 넘어간다.

- **반려·놓친 결함·과교정** → 규칙 문장으로 쓰고, 자리는 [writing-guide 「역할」](../../../contexts/writing-guide/map.md#역할)이 정한다.
  - 반려된 표현 줄은 rejected.md [줄 꼴](../../../contexts/writing-guide/rejected.md#줄-꼴)을 따른다.
  - **판단이 남는 규칙은 common.md에 산문으로 둔다.** 기계가 판정 못 하는 것을 목록으로만 옮기면 적발 0건이 「통과」로 읽혀 규칙이 사라진다.
- **출발점 오판** → write-doc 초안 단계([draft.md](../../write-doc/steps/draft.md))의 재료 받기 질문 문구를 고친다.
- **잘 읽힌 새 글 골격** → [article/skeletons.md](../../../contexts/writing-guide/types/article/skeletons.md)에 어떤 상황에서 쓴 골격인지와 함께 누적하는 백로그 항목으로 낸다. 이 파일은 골격을 고르는 쪽만 참조하고 있어, 여기서 되돌려 쌓지 않으면 처음 만든 몇 개에 고정된다.
