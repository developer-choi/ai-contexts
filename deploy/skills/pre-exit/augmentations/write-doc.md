# write-doc 세션 보강

세션에서 `/write-doc`을 사용한 경우의 추가 회고. pre-exit 본 절차와 **함께** 수행한다 (대체 X, 추가 ○).

채택된 write 도구(write-doc)의 상시 강화회고 루프다. 실문서를 다듬을 때마다 결과물을 채점하고 교정 사례를 회수해 writing-guide·스킬 본문으로 환류한다. 회고 거리는 세 종류다 — **객관(분량 등 숫자)·반객관(기계 매칭)은 채점기가 자동으로 띄우고, 주관(톤 교정·만족)은 사람이 채운다.**

## 회고 대상 1: 객관·반객관 자동채점

`score.mjs`를 산출물에 돌려 객관·반객관 결과를 회고 입력으로 띄운다. 사람은 주관(만족·추가교정)만 채운다. 기계 적발 합계는 write-doc 다듬기 검수의 채점 스크립트 검사에서 0으로 닫혔거나 잔여가 보고된 상태로 넘어오므로, 이 실행은 최종 재확인 + 분량·`--props`·누적 토큰/턴까지 포함한 완전한 회고 역할이다.

실행 명령:

```
node {{skill_dir}}/../write-doc/scripts/score.mjs <산출물.md> [--props 명제리스트.txt] [--tokens N] [--turns N]
```

`--tokens`·`--turns`는 자동 산출이 안 되므로 세션에서 얻은 누적치를 직접 넘긴다.

채점기가 띄우는 것:

- **객관** — 분량(자·문장·어절)·토큰·턴. 숫자 그대로.
- **반객관** — 금지어·반려 표현·문장부호·내부 작업이력·빈 섹션·남은 주석 등 기계 매칭 위반. 위반 개수와 해당 줄을 출력하고, 기계 적발 합계에 들어가는지는 항목마다 출력이 「합계에서 뺌」·「눈으로 확인」으로 표시한다.

무엇을 잡는지 전부 보려면 `node {{skill_dir}}/../write-doc/scripts/score.mjs --rules`로 낸다.

반객관은 한국어 단어 경계가 없어 false positive가 난다(`유사` in `유사성`). 출력된 줄을 눈으로 확인하고, 실제 위반만 아래 「반영 위치」로 보낸다.

## 회고 대상 2: 누적된 교정 사례 (주관)

세션에서 메인이 누적한 `(원본, 수정, 사유)` 톤 교정 사례 목록을 사용자에게 보여준다 (별도 로그 파일을 만들지 않는다. 메인이 대화 컨텍스트에서 직접 회수한다). write-doc 마무리 단계의 반려 적재가 이미 사용자 승인을 받아 쌓은 반려는 빼고, 거기서 다루지 않은 것만 낸다 — 같은 교정을 사용자가 두 번 승인하지 않게 한다.

각 사례를 `{원본 → 수정 → 드러난 톤 선호}` 한 줄로 정리한다.

## 회고 대상 3: write 특화 점검

이번 세션의 다듬기에서 아래가 있었는지 점검한다. 채점기가 못 잡는 판단 품질이라 사람이 회수한다.

- **리뷰어가 잡은 결함** — 검수가 `block`으로 짚어 고쳐진 톤·표현 위반. 반복 유형이면 규칙·금지어로 굳힐 후보.
- **아무도 못 잡은 결함** — 사용자가 뒤늦게 짚은 위반(채점기·리뷰어 둘 다 못 잡음). 새 규칙·금지어·grep 보강 1순위.
- **과교정** — 멀쩡한 표현을 위반으로 오판해 고쳤다가 사용자가 되돌린 것. 규칙이 과하게 넓거나 리뷰어가 고확신 기준을 낮게 잡았다는 신호다. 결함을 찾으라고 세운 리뷰어는 멀쩡한 표현까지 깎아 본문을 밋밋하게 만드는 쪽으로 실패하므로 매 회차 본다.
- **사용자의 말을 문 지적** — 사용자가 직접 쓰거나 불러넣은 구절을 리뷰어가 반려한 것. 그 구절을 브리프에 안 넘겼다는 신호다.
- **출발점 오판** — 사용자가 들고 온 재료(구상·메모·초안·예전 글)를 잘못 읽어, 초안을 두고 새로 쓰거나 재료에 없는 핵심 문장을 후보 없이 확인만 받았던 것. 무엇을 들고 왔는지 묻는 질문이 모호했는지 점검.

## 회고하지 않는 것

- **사실 오류 수정.** write-doc 다듬기는 표현만 다룬다. 사실 교정은 초안 단계 책임이라 규칙화 대상이 아니다.
- **그 문서 한정 일회성 표현 선택.** 해당 패키지·맥락에서만 유효했던 선택은 일반화하지 않는다. 반복될 톤 선호만 규칙화한다.

## 반영 위치

회수한 항목은 환류 대상에 따라 가른다:

- **톤 교정 사례·놓친 결함·과교정** → pre-exit 「문제 리스트업 + 규칙화」에서 백로그 항목으로 낸다. 항목이 넣을 자리는 [writing-guide](../../../contexts/writing-guide/map.md)의 규칙 + before/after 한 쌍이고, 사례는 규칙과 같은 맥락(해당 examples 파일)에 둔다. 앞으로 막을 낱말·표현이면 넣을 자리는 writing-guide [rejected.md](../../../contexts/writing-guide/rejected.md)이고, 줄 꼴(레인 포함)은 그 파일을 따른다.
  - **판단이 남는 규칙은 tone.md에 산문으로 둔다.** 기계가 판정 못 하는 것을 목록으로만 옮기면 적발 0건이 「통과」로 읽혀 규칙이 사라진다.
- **출발점 오판** → write-doc 초안 단계([draft.md](../../write-doc/steps/draft.md))의 재료 받기 질문 문구를 고치는 백로그 항목으로 낸다.
- **잘 읽힌 새 글 골격** → [article/skeletons.md](../../../contexts/writing-guide/types/article/skeletons.md)에 어떤 상황에서 쓴 골격인지와 함께 누적하는 백로그 항목으로 낸다. 이 파일은 골격을 고르는 쪽만 참조하고 있어, 여기서 되돌려 쌓지 않으면 처음 만든 몇 개에 고정된다.

## 출력

본 보강은 별도 보고 섹션을 만들지 않는다. 채점기 출력과 회수한 교정 사례·특화 점검 결과를 pre-exit 「문제 리스트업 + 규칙화」의 문제 목록(선호 신호)에 합류시켜, 그 규칙화 단계에서 위 「반영 위치」대로 처리한다. 채점 위반·교정 사례가 모두 0건이면 "write-doc 채점·교정 사례 없음"으로 보고하고 넘어간다.
