# write-doc — 글 쓰기

## 목적

글의 내용을 사용자와 함께 확정하고, 표현을 다듬어, 발행처에 올린다. 한 세션에서 초안부터 발행까지 이어 간다 — 초안 단계의 대화(반려·의도)가 다듬기까지 이어진다.

## 입력

`/write-doc <type> [<subtype>]` 형태로 호출한다.

| type | subtype | 필수/선택 | 설명 |
|------|---------|----------|-----|
| `pr-body` | (없음) | 선택 | 일반 PR 본문 |
| `pr-body` | `recruitment` | 선택 | 채용용 PR 본문 |
| `readme` | — | — | README (subtype 미사용) |
| `pr-comment` | `reviewer` | **필수** | 검토자가 남의 PR에 코멘트 |
| `pr-comment` | `author` | **필수** | 작성자가 자기 PR에 답글 |
| `decision` | — | — | 기술적 의사결정 문서 |
| `article` | — | — | 기술 글·가이드 |
| `case-study` | — | — | README에서 링크하는 문제→해결 사례집 |
| `note` | — | — | 학습 필기·설명 노트. 글 종류 규칙 없이 공통 톤 규칙만 걸린다 |

필수 subtype이 빠졌거나 오타면 한 번 묻고 진행한다.

이미 쓴 글을 다듬으려면 같은 형태로 부르고 초안 단계의 재료 받기에서 그 글을 건넨다. 건넨 재료가 이미 완성된 글(필수 필드를 갖춘 패키지, 또는 레포에 있는 문서)이면 초안 단계를 건너뛰고 다듬기부터 한다.

## 흐름

단계마다 그 단계에 들어갈 때 해당 파일을 Read하고 그대로 따른다. 앞 단계가 끝나면 사용자에게 넘기지 않고 다음 단계로 이어 간다.

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 초안 | [steps/draft.md](steps/draft.md) | 재료 받기 → 핵심 문장 합의 → 골격 → 내용 채움 → 패키지 저장 → 사용자 채움 |
| 다듬기 | [steps/polish.md](steps/polish.md) | 표현·톤·분량을 다듬고 채점 스크립트·리뷰어로 검수 |
| 마무리 | [steps/finish.md](steps/finish.md) | 남은 주석 확인 → 반려 적재 → 발행처 양식 대조 → 발행 |

## 모든 단계에 걸리는 것

- **컨텍스트가 어긋나면 frontmatter가 정본이다.** 대화·compact 요약에 남은 잔재가 패키지 frontmatter와 다르면 frontmatter를 따른다. 승인본과 어긋날 때도 frontmatter가 앞선다.
- **사용자가 지운 절·문장은 다시 넣지 않는다.** 필요해 보이면 되살릴지 묻는다.
- **사용자가 거부한 것은 그때마다 패키지 frontmatter `rejected`에 적는다.** 모든 글로 올릴 만해 보여도 여기에 먼저 적는다 — 마무리 단계가 이 목록을 재료로 어디에 쌓을지 가르고, 긴 세션이 압축돼도 파일에 남는다. 한 번 거부된 결의 표현은 다음 수정에 다시 넣지 않는다.
- **승인본(같은 성격으로 이미 승인된 글)에서는 분량·절 수·말투만 가져온다.** 사실은 가져오지 않는다.
