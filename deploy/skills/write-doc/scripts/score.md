# score.mjs 사용법

`node <write-doc 스킬 폴더>/scripts/score.mjs <산출물.md> [옵션]` 또는 `… score.mjs --rules`

글을 객관(분량 등)과 반객관(기계 매칭 위반)으로 따로 채점해 stdout에 낸다. 점수로 합치지 않는다. 줄 번호 `L`은 frontmatter를 포함한 파일 기준이다.

## 모드

- `<산출물.md>` — 전체 채점. 끝에 `>> 기계 적발 합계(참고용, 점수 아님): N건 + 눈으로 확인 후보 M건(…)`. exit 0
- `--rules` — 무엇을 잡는지(낱말·경고 레인·대체어) 낸다. 산출물을 받지 않는다
- `<산출물.md> --structure` — 긴 문단·개수 선언 뒤 리스트 없음만 낸다. 톤을 다듬기 전, 내용을 채운 초안의 나눔만 볼 때 쓴다
- `<산출물.md> --residual` — 남은 `[//]: #` 주석만 낸다. 있으면 `남은 주석 N건 — …`과 exit 1, 없으면 `남은 주석 없음`과 exit 0. 발행 직전 확인용

## 전체 채점에 붙이는 옵션

- `--props <명제리스트.txt>` 한 줄에 핵심 명제 하나. 본문에 그대로 들어 있는지만 본다. 빠진 명제는 합계에서 빼고 따로 낸다
- `--tokens <N>`·`--turns <N>` 세션에서 얻은 값. 객관 표에 기록만 한다
- `--json` 사람용 출력 끝에 기계용 `@@score {total,titleHits,refHits}` 한 줄을 추가한다(`publish-pr.mjs`가 읽는다)

## 출력 읽는 법

- 첫 줄 `모든 글 반려: …`는 writing-guide `rejected.json`을 읽은 자리나 건너뛴 까닭이다. 배포본을 읽으므로 원본에 새로 올린 항목은 배포 뒤에 잡힌다
- 항목 이름 뒤에 `(합계에서 뺌 — …)`·`(눈으로 확인 …)`이 붙은 것은 쓰임을 보고 실제 위반만 고른다. 위반마다 그 줄을 함께 내므로 오탐을 눈으로 가른다
- `→`로 시작하는 줄은 그 항목을 어떻게 고치는지다
- 주관(만족·추가교정)은 재지 않는다

산출물 경로가 없으면(`--rules` 밖) 사유와 이 문서 경로를 stderr에 내고 exit 1.
