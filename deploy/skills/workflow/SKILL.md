# 워크플로우

## 목적

기획서·피그마·디자인토큰·채용과제처럼 코딩의 바탕이 되는 원본 문서를 받아, 배경 파악부터 코드리뷰까지의 단계를 거쳐 PR까지 만들어내는 공정이다.

서로 기다릴 필요 없는 일을 겹쳐 돌려, 앞 단계가 끝날 때까지 뒤가 노는 대기를 없애는 것이 목적이다.

## 호출

`/workflow <세션 이름> <모드> [--prefix <접두어>] [--plan <plan 경로>]`

- 세션 이름·모드는 기본값이 없다. 사용자가 직접 넘긴다.
- 세션 이름: `BG` / `MARKUP` / `PR_{N}_PLAN` / `PR_{N}_IMPL` / `FINALIZE`
- 모드: `채용` / `실무` / `개인`
- 접두어: 후속 세션 이름 앞에 붙는다(`<접두어>_PR_1_PLAN`). 세션 이름 인자에는 붙이지 않고 `--prefix`로 따로 준다. 개인 모드는 필수다 — 개인 작업 여러 건을 나란히 돌리면 세션 이름과 plan 폴더가 겹친다
- plan 경로: 이 작업의 plan 폴더. 생략하면 개인 모드는 `plan/<접두어>`, 실무·채용 모드는 `plan`이다(메인 레포 루트 기준)

## 구조

기획서·피그마에서 PR까지 가는 일을 서로 기다리지 않고 겹쳐 진행하기 위해 세션·step·모드·PR을 종류별로 나눈다.

- 세션: AI 세션 하나가 맡는 일의 단위다. 예를 들어 `BG` 세션은 자료를 받아 요구사항을 분석하고 PR을 나눈다.
- step: 기획서·피그마를 PR까지 만드는 과정을 단계로 나눈 것이다. 기획서 분석 → 개발 계획 수립 → 구현 → 코드리뷰 같은 현실의 작업마다 step이 있고, step은 그 단계에서 쓸 하위 스킬을 오케스트레이션한다. 세션 하나가 step 여러 개를 이어 밟기도 한다.
- 모드: 작업이 놓인 상황을 나눈 것이다. 예를 들어 `채용`·`실무` 모드는 피그마를, `개인` 모드는 직접 만든 마크업 시안을 디자인 기준으로 삼는다.
- PR: 흔히 나오는 PR은 종류별 프리셋이 있다. 예를 들어 `FOUNDATION`(코드 스타일 기준), `COMPONENTS`(공통 UI 컴포넌트).

PR과 세션의 관계: 세션은 PR 하나를 맡거나 작업 전체를 맡는다. PR 하나는 여러 세션이 나눠 맡는다 — 예를 들어 2번째 PR은 `PR_2_PLAN` 세션이 설계하고 `PR_2_IMPL` 세션이 구현한다. 커밋 히스토리 정리처럼 작업 전체에 걸친 일은 `FINALIZE` 세션이 한다.

## 세션 진행

### 시작할 때
- BG 세션이면 [conventions/session-args.md](conventions/session-args.md)대로 인자를 확정한다
- 그 밖의 세션은 `node {{skill_dir}}/scripts/steps.mjs start <세션> --mode <받은 모드> [--prefix <받은 접두어>] [--plan <받은 plan 경로>]`를 돌린다
  - 실패하면 작업을 시작하지 않고 빠진 값을 사용자에게 묻는다
  - 통과하면 그 출력대로 진행하고, 이후 plan을 받는 호출에는 출력이 찍은 plan 값을 쓴다
- `start`가 찍은 plan 폴더로 이전 step 산출물과 맥락을 파악한다. 기억해 둔 내용이 아니라 파일의 현재 상태를 기준으로 한다
  - 메인 에이전트는 컨텍스트에 산출물 본문이 쌓이지 않게 폴더의 파일 목록과 `node {{skill_dir}}/scripts/steps.mjs pr list` 출력만 본다
  - 산출물 내용은 일회성 서브에이전트에 맡겨, 산출물마다 무엇을 정해 두었는지 요약만 돌려받는다. 읽고 요약만 하는 일이라 더 가벼운 모델로 띄우고, 고른 모델과 근거를 사용자에게 알린다
  - 요약은 step 입력을 대신하지 않는다 — step이 쓸 입력은 그 step 문서가 정한 대로 읽는다
  - plan 폴더가 아직 없으면(BG 초반) 파일 목록과 `pr list`를 건너뛴다. 파일 목록에 이전 step 산출물이 없으면 서브에이전트를 띄우지 않는다
- 맥락이 부족하면 사용자에게 질문한다
- 이전 step을 이 세션에서 거치지 않았어도 진입할 수 있다. 단 `start`가 찍은 진입 조건은 지킨다

### 진행 중
- 리뷰·검증은 원본 자료(figma 원본, 컨벤션 1차 소스, 사용자 발화 등)와 대조한다
- 이 세션에 결론만 있으면 되고 과정은 다시 쓰지 않는 작업은, 사용자가 시킨 일이어도 시작하기 전에 [conventions/side-session.md](conventions/side-session.md)의 방아쇠를 보고 별도 세션으로 뺄지 묻는다. 서브에이전트로 조사하라·직접 검증하라는 지시도 수단을 정한 것일 뿐이라, 그 지시를 받았어도 묻는다
  - 그런 작업의 예: 결정 하나의 근거를 대려고 외부 문서·라이브러리 소스를 여러 곳 읽기(WebFetch·WebSearch·소스 내려받기로 직접이든 서브에이전트든), 재현용 앱·페이지 제작, 원인 가설이 2번 틀린 버그의 3번째 가설 등

### step을 넘길 때
- 같은 세션에서 다음 step으로 넘어가기 전에 사용자 승인을 받는다

### 후속 세션 안내

사용자가 이 스킬의 내부 구현을 기억하지 않아도 되도록, 다음에 열 세션을 AI가 먼저 안내한다.

- 안내 시점
  1. step이 끝났을 때
  2. step 도중, 그 step 문서의 frontmatter가 정해 둔 사건이 일어났을 때. 일어나는 즉시, 일어날 때마다 안내하고 하던 일을 이어간다.
- 안내할 내용: `start`가 「후속 안내 때 이 줄을 그대로 쓴다」로 찍은 줄의 `<끝난 step>` 자리에 현재 step을 넣어 돌리고, 그 출력을 사용자에게 전한다.
