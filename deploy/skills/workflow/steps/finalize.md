# finalize: 전 PR 최종화

모든 PR의 구현이 끝난 뒤 **1회**, 전 PR 커밋 히스토리를 머지 직전 상태로 정리하는 세션. PR 본문 작성은 이 세션의 선행이 아니다.

## 입력·산출물·작업 위치

- **입력**: 전 PR 커밋 히스토리(각 PR 브랜치의 base..tip) + PR·브랜치 목록(머지 여부) + 계획한 PR 목록·브랜치(prs.json) + `background/consumable/todo.md` + `/plan/` 전체의 잔존 consumable(PR 본문 작성 잔여 포함)
- **산출물**: 재배치·메시지 최종화된 히스토리 + force-push 요청 / 잔존 consumable은 사용자 판단에 따라 삭제 또는 이관 (새 폴더 산출물 없음)
- **작업 위치**: 다중 브랜치 ([cwd](#cwd))

## 진입 실측

**미머지를 참으로 깔고 절차를 시작하지 않는다** — 실제 상태를 먼저 잰다.

두 원천을 **모두** 읽고 함께 고려한다.

- 이미 **머지된 PR**이 있는지
- 계획한 PR 목록(`pr list`)에 있는데 PR로 안 올라간 **미완료 작업**이 있는지

실측 결과를 (a) 머지 완료 — 일괄 조작에서 빠진다 (b) 미머지 (c) 계획한 PR 목록에만 있고 PR이 없는 미착수로 갈라 **절차 시작 전에 사용자에게 보고**한다.

계획엔 있는데 PR이 없거나 PR은 있는데 계획에 없으면, 그 어긋남을 보고하고 진행 방향을 묻는다.

계획한 PR 목록이 비어 있어도 절차는 멈추지 않는다 — PR·브랜치 목록이 폴백 원천이다. 반대로 `todo.md`가 지시하는 작업(재배치 대상 등)은 **실행 전 현재 코드·히스토리와 대조**한다. 대조는 서브에이전트에 맡기고, 지시마다 아직 유효한지만 받는다.

`node {{skill_dir}}/scripts/steps.mjs pr branches`로 PR마다 형태(스택·독립)·base·범위 커밋을 뽑는다. 커밋 소속은 접두사가 아니라 이 범위로 식별한다. 미기록·어긋남·「직접 확인」이 찍히면 사용자에게 보고한다.

## cwd

메시지 최종화는 스택이면 최상단 워크트리에서 한 번에, 독립 브랜치면 브랜치별 워크트리에서 각각 돈다. 스택이면 아래 PR 브랜치도 새 커밋을 가리키게 한다 — 아래 브랜치가 다른 워크트리에 체크아웃돼 있으면 함께 옮겨지지 않는다. 재배치로 스택 안 커밋을 옮겼을 때도 같다. 재배치·메시지 최종화를 마치면 `pr branches`를 다시 돌려 어긋남이 없는지 본다.

## 절차

### 재배치 — 오배치 커밋을 원래 PR로

**소속이 틀린(오배치)** 커밋을 원래 PR로 되돌린다. 오배치 = 그 브랜치 구간에 있지만 내용상 다른 PR 작업인 커밋이다. 소속은 맞는데 시간만 뒤섞인 커밋은 재배치하지 않는다.

판별은 팀원([team-agent](../../../contexts/team-agent.md))에게 맡겨 「커밋 → 원래 PR」 목록만 받는다. 사용자가 그 목록을 고친 뒤 옮긴다.

cherry-pick이 충돌하면 그 커밋이 실은 원본 PR의 맥락에 얽혀 있다는 신호이므로 재배치가 옳은지 사용자와 재확인한다.

### 메시지 최종화 — 슬라이스·도메인 재작성 + 톤 정리

재배치를 마친 뒤 전 커밋의 메시지를 슬라이스·도메인 기준으로 재작성하고, **외부 독자(채용담당자·리뷰어·팀원) 친화 톤으로 정리**한다. net-diff 불변(코스메틱). 톤 가이드는 [커밋 메시지 톤 — 외부 독자 친화](../conventions/commits.md#커밋-메시지-톤--외부-독자-친화) 참조.

- 슬라이스 분할·stub 처리는 각 PR의 verify [커밋 정리](verify.md#step-625-커밋-정리--사용자-리뷰-전)·[fixup 합치기](verify.md#step-65-fixup-합치기)가 끝냈다 — 다시 하지 않는다.
- 커밋 메시지와 함께 `todo.md` 등 외부 노출 가능 메모도 톤 스캔한다.
- 재작성안과 톤 스캔은 팀원에게 맡겨 「옛 문구 → 새 문구」 표(커밋 메시지·메모를 갈라서)만 받는다. 사용자가 고친 표대로 메시지와 메모를 바꾼다.

### force-push

재배치·메시지 최종화 완료 후 사용자에게 force-push를 요청한다.

### consumable 잔존 점검

force-push 요청 후 `node {{skill_dir}}/scripts/plan-folder.mjs left /plan`으로 잔존 consumable을 뽑는다. 안내문 누락분도 잔존으로 다룬다.

- 잔존 파일이 있으면 절마다 같은 내용이 이미 다른 파일에 있는지 먼저 검색한다. 검색·이관 규칙은 [산출물 정리](pr-body-final.md#산출물-정리)와 같다. 검색은 서브에이전트에 맡기고 절마다 결과 한 줄만 받는다.
- 경로 목록에 절마다 검색 결과(무엇으로 찾았는지, 없음 / 어느 파일에 있고 판본 차이는 무엇인지)를 붙여 사용자에게 제시하고 **"이 중 교훈으로 남길 게 있는지"** 묻는다.
- 없다고 답하면 그 자리에서 삭제한다. 있다고 답한 파일은 어디로 옮길지(예: `persistent/`로 승격, KA 백로그로 이관) 사용자와 정하고, 옮길 때는 [산출물 정리](pr-body-final.md#산출물-정리)의 이관 규칙을 따른다.

## PR 본문 작성·머지 관계

- **PR 본문을 이 세션 전에 쓴 PR**: 재배치로 커밋 구성이 바뀐 PR은 본문 수치·서술을, 본문에 커밋 링크가 있으면 메시지 최종화로 SHA가 바뀌므로 모든 PR의 링크를 대조한다. 대조는 서브에이전트에 맡기고 어긋난 곳 목록만 받아 사용자에게 보인다. 고칠지는 사용자가 정한다.
- **머지**: 본 세션(재배치 + 메시지 최종화 + force-push)은 먼저 머지한 PR을 빼면 **첫 머지보다 앞**이다.

## 머지된 PR 처리

이미 머지된 PR은 **본 세션의 일괄 조작(재배치 + 메시지 최종화) 대상에서 빠진다.**

- 전 PR이 이미 머지돼 재배치·메시지 최종화·force-push가 모두 성립하지 않으면, 본체를 건너뛴다고 보고하고 「consumable 잔존 점검」과 「후속 안내」로 간다. 세션을 끝내지 않는다.

## 후속 안내 (모드 분기)

- **채용** — 새 세션을 안내하지 않고 본 세션이 [recruitment/SKILL.md](../recruitment/SKILL.md)를 처음부터 이어서 수행한다.
- **실무·개인** — 머지 순서를 안내하고 세션을 끝낸다(스택은 바텀업, 독립 브랜치는 순서 무관). 머지는 사용자 실행.
