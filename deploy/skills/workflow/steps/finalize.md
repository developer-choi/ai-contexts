# finalize: 전 PR 최종화

모든 PR의 IMPL이 끝난 뒤 **1회**, 전 PR 커밋 히스토리를 머지 직전 상태로 정리하는 세션. WRITING(PR 본문)은 본 세션의 선행이 아니다 (「WRITING·머지 관계」).

## 입력·산출물·작업 위치

- **입력**: 전 PR 커밋 히스토리(각 PR 브랜치의 base..tip) + PR·브랜치 목록(머지 여부) + 계획한 PR 목록(`node {{skill_dir}}/scripts/steps.mjs pr list --plan /plan`) + `background/consumable/todo.md` + `/plan/` 전체의 잔존 consumable(WRITING 잔여 포함)
- **산출물**: 재배치·메시지 최종화된 히스토리 + force-push 요청 / 잔존 consumable은 사용자 판단에 따라 삭제 또는 이관 (새 폴더 산출물 없음)
- **작업 위치**: 다중 브랜치, 단계별 cwd ([cwd](#cwd))

## 진입 실측

**미머지를 참으로 깔고 절차를 시작하지 않는다** — 실제 상태를 먼저 잰다.

두 원천을 **모두** 읽고 함께 고려한다.

- 이미 **머지된 PR**이 있는지 (「머지된 PR 처리」)
- 계획한 PR 목록(`pr list`)에 있는데 PR로 안 올라간 **미완료 작업**이 있는지

실측 결과를 (a) 머지 완료 (b) 미머지 (c) 계획한 PR 목록에만 있고 PR이 없는 미착수 로 갈라 **절차 시작 전에 사용자에게 보고**한다. 양쪽이 어긋나면(계획엔 있는데 PR이 없다 / PR은 있는데 계획에 없다) 그 어긋남 자체를 보고하고 진행 방향을 묻는다.

계획한 PR 목록이 비어 있어도 절차는 멈추지 않는다 — PR·브랜치 목록이 폴백 원천이다. 반대로 `todo.md`가 지시하는 작업(replace 대상 등)은 **실행 전 현재 코드·히스토리와 대조**한다.

커밋 소속은 접두사가 아니라 **브랜치**(각 PR 브랜치의 base..tip 범위)로 식별한다.

**브랜치 형태는 PR마다 다르다.** 앞 PR에 의존하는 PR은 그 브랜치 위에 얹혀 있고(스택), 독립인 PR은 기본 브랜치에서 각자 뻗어 있다 (base 결정은 [사전 준비](realize-plan.md#사전-준비-브랜치워크트리-생성) — 사용자 확인 사항).

## cwd

메시지 최종화는 스택이면 최상단 워크트리에서 한 번에, 독립 브랜치면 브랜치별 워크트리에서 각각 돈다.

## 절차

### replace — 오배치 커밋을 원래 PR로 재배치

"PR4에 있지만 실은 PR2 작업인 커밋"처럼 **소속이 틀린(오배치)** 커밋을 원래 PR로 되돌린다. 오배치 = 그 브랜치 구간에 있지만 내용상 다른 PR 작업인 커밋. 시간순 섞임(소속은 맞는데 시간만 뒤섞임)과 구분한다 — 후자는 재배치 대상이 아니다.

cherry-pick이 충돌하면 그 커밋이 실은 원본 PR의 맥락에 얽혀 있다는 신호이므로 재배치가 옳은지 사용자와 재확인한다.

전 PR이 다 완성돼야 오배치를 되돌릴 수 있다 — 구현 페이즈 도중엔 대상 PR이 아직 열려 있어 재배치할 곳이 확정되지 않는다. 그래서 종료 페이즈 1회 조작이다.

### 메시지 최종화 — 슬라이스·도메인 재작성 + 톤 정리

전 커밋의 메시지를 슬라이스·도메인 기준으로 재작성하고, **외부 독자(채용담당자·리뷰어·팀원) 친화 톤으로 정리**한다. net-diff 불변(코스메틱). 톤 가이드는 [커밋 메시지 톤 — 외부 독자 친화](../conventions/commits.md#커밋-메시지-톤--외부-독자-친화) 참조.

- 슬라이스 분할·stub drop은 각 PR의 [verify 「1회차 커밋 정리·재정렬」](verify.md#step-65-1회차-커밋-정리재정렬)에서 이미 끝났으므로, 본 세션은 메시지 정리에 집중한다.
- 커밋 메시지와 함께 `todo.md` 등 외부 노출 가능 메모도 톤 스캔한다.

### 순서

**replace 먼저(소속 교정) → 메시지 최종화(재작성 + 톤)** 순차.

### force-push

replace·메시지 최종화 완료 후 사용자에게 force-push를 요청한다.

### consumable 잔존 점검

force-push 요청 후, `background/consumable/`을 포함한 `/plan/` 전체를 훑어 잔존 consumable이 있는지 확인한다 ([남은 consumable 조회](../conventions/plan-folder.md#consumable-산출물-자가-정리-안내문)).

- 잔존 파일이 있으면 절마다 같은 내용이 이미 다른 파일에 있는지 먼저 검색한다. 검색 방법은 [산출물 정리](pr-body-final.md#산출물-정리)와 같다.
- 경로 목록에 절마다 검색 결과(무엇으로 찾았는지, 없음 / 어느 파일에 있고 판본 차이는 무엇인지)를 붙여 사용자에게 제시하고 **"이 중 교훈으로 남길 게 있는지"** 묻는다.
- 없다고 답하면 그 자리에서 삭제한다. 있다고 답한 파일은 어디로 옮길지(예: `persistent/`로 승격, KA 백로그로 이관) 사용자와 정한다. 다른 consumable 파일로는 옮기지 않는다. `/plan/` 밖으로 옮기면 옮겨갈 곳도 같은 방식으로 검색한다.

## WRITING·머지 관계

- **WRITING을 replace 전에 쓴 PR**: replace로 그 PR 커밋 구성이 바뀌면 해당 PR 본문만 사후에 손본다 (하드 게이트 아님 — 사용자 판단. 커밋 링크·수치가 어긋났는지 확인).
- **머지**: 본 세션(replace + 메시지 최종화 + force-push)은 **첫 머지보다 앞**이다. 채용 모드는 PR 게시도 본 세션의 replace·메시지 최종화·force-push가 끝난 뒤에 시작한다. **스택으로 얹힌 PR은 바텀업(아래→위)으로 머지**하고, 독립 브랜치는 순서 제약이 없다. 머지 자체는 사용자가 실행한다. 독립 PR을 본 세션 전에 먼저 머지하는 예외는 아래 「머지된 PR 처리」가 다룬다.

## 머지된 PR 처리

앞 PR에 독립인 PR은 전체 완성을 기다리지 않고 먼저 머지할 수 있다. 머지된 PR은 **본 세션의 일괄 조작(replace + 메시지 최종화) 대상에서 빠진다.**

- 먼저 머지할 PR은 **머지 직전에 그 PR만 수동으로 메시지 정리**한다
- 스택 상류가 섞여 들어가지 않도록 base retarget 또는 상류 선머지로 처리한다.
- 본 세션 진입 시 이미 머지된 PR이 있으면, 그 PR은 건너뛴다는 사실을 사용자에게 보고한다. 조용히 빼지 않는다.
- 전 PR이 이미 머지돼 replace·메시지 최종화·force-push가 모두 성립하지 않으면, 본체를 건너뛴다고 보고하고 「consumable 잔존 점검」과 「후속 안내」로 간다. 세션을 끝내지 않는다.

## 후속 안내 (모드 분기)

본문을 마치면 모드별로 갈린다.

- **채용** — 새 세션을 안내하지 않고 본 세션이 [recruitment/SKILL.md](../recruitment/SKILL.md)를 1번부터 이어서 수행한다(PR 게시·README·채용담당자 리뷰·제출·제출 뒤 회수). 제출 뒤 회수([recruitment/after-submission.md](../recruitment/after-submission.md))는 컨텍스트가 커졌으면 새 세션으로 옮겨도 된다고 제출을 마친 시점에 안내하고, 옮기면 그 파일 경로를 새 세션에 넘기게 한다.
- **실무·개인** — 머지 순서를 안내하고 세션을 끝낸다(스택은 바텀업, 독립 브랜치는 순서 무관). 머지는 사용자 실행.
