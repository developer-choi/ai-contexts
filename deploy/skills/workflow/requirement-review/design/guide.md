# 디자인 시안 리뷰 가이드

기획서 리뷰(planning)의 산출물(page.md, global.md)이 이미 있으면 보완하고, 없으면 디자인 시안을 기반으로 신규 생성한다.

**개인 모드**는 사용자가 미리 만든 마크업 시안(`background/retained/mockup/`)이 디자인 원본이다 — step-1.1에서 받는다. 이 시안을 참조해 의도·구조를 page.md/global.md에 반영하고 사용자 확인을 받는다. 시각 충실도는 MARKUP의 시안 대조 + 사용자 시각 확인이 담당하므로([steps/markup/personal.md](../../steps/markup/personal.md)) 본 단계는 비시각 의도·구조 정의에 집중한다.

**코드기반 모드**는 시안이 없고 기존 구현 코드가 있는 경우다 — planning의 코드기반 모드와 짝을 이룬다. 디자인 시안을 분석하는 대신 기존 코드의 실제 스타일·레이아웃·인터랙션을 읽어 디자인 체크리스트에 대입한다. 디자인↔기획서 불일치 대조 대신, 코드에서 읽어낸 현재 동작을 page.md/global.md에 반영하고 사용자 확인을 받는다.

## 슬롯

### 준비 방식

#### 맥락 수집

기획서 리뷰가 선행된 경우 그 맥락을 기반으로, 아닌 경우 처음부터 확인합니다:

- 디자인 시스템이나 스타일 가이드가 있는지
- 디자인 시안의 범위 (기획서와 다른 부분이 있는지)

### 입력 자료

페이지 단위의 디자인 시안 자료.

### 체크리스트

`checklist/` 하위의 디자인 체크리스트를 적용합니다.

페이지 유형을 식별하고, 해당하는 `../page-type/` 체크리스트를 추가 적용합니다.

### 산출물

- `/plan/background/consumable/global.md` — 디자인 관련 공통 컴포넌트, TODO
- `page.md` — 디자인 분석 결과. 저장 위치는 [planning/guide.md](../planning/guide.md) 「산출물」의 page.md 규칙과 같다

### 분석 과정

#### 같이 분석

체크리스트 슬롯에서 정의한 체크리스트를 page.md에 적용합니다:

1. 디자인 상세(간격, 색상, 타이포, 반응형, 인터랙션 등)를 짚습니다. 기획서 리뷰가 선행된 경우, 기획서에서 다루지 못한 부분을 중점적으로 봅니다.
2. 디자인과 기획서 간 불일치가 있으면 사용자에게 알립니다.
3. 초안과 발견한 문제를 사용자에게 제시합니다.

#### 종합

design 단독(planning 꺼짐)이면 design 관점의 종합만 수행한다: 공통화 검토([planning/guide.md](../planning/guide.md) 「종합」 2번), 페이지 간 디자인 패턴 일관성 점검.
