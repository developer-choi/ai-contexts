# 디자인 시안 리뷰 가이드

## 슬롯

### 준비 방식

#### 맥락 수집

리뷰 시작 전, 받은 자료와 이미 적힌 산출물로 답이 나오지 않은 것만 사용자에게 묻는다.

- 디자인 시스템이나 스타일 가이드가 있는지
- 반응형 범위

#### 산출물 생성

planning이 켜져 있으면 그 산출물(page.md·global.md)을 보완한다.
꺼져 있으면 planning [산출물 생성](../planning/guide.md#산출물-생성)대로 루프 대상 페이지를 정하고 global.md·page.md를 만든다.

### 입력 자료

페이지 단위의 디자인 시안 자료.

### 체크리스트

페이지마다 [페이지 체크리스트](./checklist/page.md)를, 그 페이지에서 새로 만들 컴포넌트마다 [컴포넌트 체크리스트](./checklist/component.md)를 적용하고, [공통 체크리스트](./checklist/common.md)는 둘 다에 적용한다.
planning이 꺼져 있으면 페이지 유형에 맞는 `../page-type/` 체크리스트를 추가 적용한다.

### 산출물

- `/plan/background/consumable/global.md` — 공통 컴포넌트(구조 관찰)·반응형 정책
- `page.md` — 위치·이동은 [conventions/plan-folder.md](../../conventions/plan-folder.md)

체크리스트 결과는 컴포넌트에 걸리면 「구조 관찰」, 로딩·에러 UI는 API 칸, 빈 상태 UI와 이 페이지의 반응형 차이는 「페이지 동작」에 적는다.

### 분석 과정

#### 자료 참조

**개인 모드**는 사용자가 미리 만든 마크업 시안(`background/retained/mockup/`)이 디자인 원본이다.
이 시안으로 의도·구조를 page.md/global.md에 반영하고, 시안으로 답이 정해지는 시각 항목은 옮기지 않는다.
확정 단계의 대조 서브에이전트에도 이 기준을 넘겨, 시각 항목을 누락으로 치지 않게 한다.

**코드기반 모드**는 시안 대신 기존 코드의 스타일·레이아웃·인터랙션에 디자인 체크리스트를 대입해, 현재 동작을 page.md/global.md에 반영한다.
대상 코드는 planning [코드기반 모드](../planning/guide.md#자료-참조)의 코드 읽기 팀원(`workflow-code-reader`)에게 맡기고, 디자인 `checklist/` 폴더 경로(planning이 꺼져 있으면 `../page-type/`도)를 넘긴다.

#### 같이 분석

AI가 자료와 체크리스트로 page.md를 채운다:

1. 체크리스트 항목마다 자료에서 확인한 내용을 「산출물」이 정한 칸에 적는다. 자료에서 확인되지 않는 항목은 `[?]`로 표기한다.
2. 채팅에 `[?]` 항목과 발견한 문제(이미 적힌 page.md 내용과 자료가 어긋나는 곳 포함)를 나열한다. **여기서 멈추고 사용자 응답을 기다린다.**

#### 종합

design 단독(planning 꺼짐)이면 design 관점의 종합만 한다: [종합](../planning/guide.md#종합)의 공통화 검토, 페이지 간 디자인 패턴 일관성 점검.
공통화 후보 찾기와 디자인 패턴 점검은 메인이 하지 않고 일회성 서브에이전트에 맡긴다. 모든 page.md(planning 「종합」과 같은 범위)와 global.md의 경로를 넘긴다.
공통화 후보(후보마다 쓰이는 페이지)와 페이지 간 어긋난 디자인 패턴(패턴·해당 페이지)만 돌려받되, 항목마다 근거 `파일:줄`과 그 원문 줄을 붙이게 한다.
