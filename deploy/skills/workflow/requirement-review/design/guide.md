# 디자인 시안 리뷰 가이드

## 슬롯

### 준비 방식

#### 맥락 수집

리뷰 시작 전, 받은 자료와 앞선 리뷰(planning·recruitment)로 답이 나오지 않은 것만 사용자에게 묻습니다.

- 디자인 시스템이나 스타일 가이드가 있는지
- 반응형 범위 (모바일 온리 / PC+Mobile 등)
- 디자인 시안의 범위 (기획서와 다른 부분이 있는지)

#### 산출물 생성

planning이 켜져 있으면 그 산출물(page.md·global.md)을 보완합니다.
꺼져 있으면 planning [산출물 생성](../planning/guide.md#산출물-생성)대로 루프 대상 페이지를 정하고 global.md·page.md를 만듭니다.

### 입력 자료

페이지 단위의 디자인 시안 자료.

### 체크리스트

페이지마다 `checklist/page.md`를, 그 페이지에서 새로 만들 컴포넌트마다 `checklist/component.md`를 적용하고, `checklist/common.md`는 둘 다에 적용합니다.
planning이 꺼져 있으면 페이지 유형에 맞는 `../page-type/` 체크리스트를 추가 적용합니다.

### 산출물

- `/plan/background/consumable/global.md` — 공통 컴포넌트(구조 관찰)·반응형 정책
- `page.md` — 위치·이동은 [conventions/plan-folder.md](../../conventions/plan-folder.md)

체크리스트 결과는 컴포넌트에 걸리면 「구조 관찰」, 로딩·에러 UI는 API 칸, 이 페이지의 반응형 차이는 「페이지 동작」에 적습니다.

### 분석 과정

#### 자료 참조

**개인 모드**는 사용자가 미리 만든 마크업 시안(`background/retained/mockup/`)이 디자인 원본이다.
이 시안으로 의도·구조를 page.md/global.md에 반영하고, 시안으로 답이 정해지는 시각 항목은 옮기지 않는다(시각 충실도는 MARKUP 몫).
SKILL 페이지 단위 루프 「확정」의 대조 서브에이전트에도 이 기준을 넘겨, 시각 항목을 누락으로 치지 않게 한다.

**코드기반 모드**는 시안 대신 기존 코드의 스타일·레이아웃·인터랙션에 디자인 체크리스트를 대입해, 현재 동작을 page.md/global.md에 반영한다.
대상 코드는 planning [코드기반 모드](../planning/guide.md#자료-참조)의 코드 읽기 팀원(`workflow-code-reader`)에게 맡기고, 디자인 `checklist/` 폴더 경로(planning이 꺼져 있으면 `../page-type/`도)를 넘긴다.

#### 같이 분석

page.md 초안에 체크리스트를 적용합니다:

1. 디자인 상세를 짚습니다. 기획서 리뷰가 선행된 경우, 기획서에서 다루지 못한 부분을 중점적으로 봅니다.
2. 디자인과 기획서 간 불일치가 있으면 사용자에게 알립니다.
3. 초안과 발견한 문제를 사용자에게 제시합니다.

#### 종합

design 단독(planning 꺼짐)이면 design 관점의 종합만 한다: [종합](../planning/guide.md#종합)의 공통화 검토, 페이지 간 디자인 패턴 일관성 점검.
이 대조는 메인이 하지 않고 일회성 서브에이전트에 맡긴다. 모든 page.md(planning 「종합」과 같은 범위)와 global.md의 경로를 넘긴다.
공통화 후보(후보마다 쓰이는 페이지)와 페이지 간 어긋난 디자인 패턴(패턴·해당 페이지)만 돌려받되, 항목마다 근거 `파일:줄`과 그 원문 줄을 붙이게 한다.
