# 기획서 리뷰 가이드

## 슬롯

### 준비 방식

#### recruitment와 함께 실행되는 경우

- 맥락 수집 질문 중 서비스 설명·기능 요약·신규 여부는 생략한다.
- checklist/purpose-nonfunctional.md의 "목적/배경 파악"은 과제의 기능 범위와 구현 목표로 대체하여 읽는다.
- 별도 기획서가 없으면 과제요구사항과 UI 목업이 기획서 역할을 한다. recruitment가 페이지별로 정리한 페이지를 루프 대상으로 쓴다.

#### 맥락 수집

리뷰 시작 전, 사용자에게 맥락을 질문합니다. 사용자가 이미 설명했다면 해당 항목은 생략합니다.

- 이 서비스가 무엇을 하는 서비스인지
- 이번에 리뷰할 기능이 무엇인지 (한 줄 요약)
- 신규 서비스/기능인지, 기존 기능 개선인지
- 알아두어야 할 배경이나 제약사항이 있는지

#### 산출물 생성

recruitment와 함께가 아니면 루프 대상 페이지는 수집된 자료(코드기반 모드면 코드 읽기 팀원이 대상 코드의 라우트·화면에서 뽑은 목록)에서 뽑아 사용자에게 확인받습니다.
[output-template.md](./output-template.md)의 global.md 템플릿을 `/plan/background/consumable/global.md`에, page.md 템플릿을 루프 대상 페이지마다 `/plan/background/consumable/page-{페이지명}.md`에 빈 템플릿으로 생성합니다.
생성한 global.md의 「개요」·「반응형 정책」·「비기능 요구사항」 칸은 맥락 수집 답과 자료에서 확인한 내용으로 루프 전에 채웁니다.

### 입력 자료

페이지 단위의 기획서 자료.

### 체크리스트

`checklist/` 하위 파일을 적용합니다. 페이지 유형을 식별하고, 해당하는 `../page-type/` 체크리스트를 추가 적용합니다.

### 산출물

- `/plan/background/consumable/global.md` — **생성**. 전체 서비스 맥락, 공통 컴포넌트
- `page.md` — **생성**. 페이지별 분석 결과 (위치·이동은 [conventions/plan-folder.md](../../conventions/plan-folder.md))
- `/plan/background/consumable/layout.md` — 「종합」에서 생성하기로 한 경우에만 **생성**

### 분석 과정

#### 자료 참조

figma URL·캡처의 저장 위치와 재요청은 [피그마 URL·캡처 캐싱](../../conventions/plan-folder.md#피그마-url캡처-캐싱). 현재 리뷰 대상과 관련 없어 보이는 자료가 있으면 사용자에게 알립니다.

**개인 모드**는 requirement 「자료 받기」가 받은 마크업 시안(`retained/mockup/`)·`retained/spec.md`(있으면)로 page.md 초안(비시각 스펙: 동작·API·메타)을 쓰고 사용자 공동 승인을 받습니다. 시안·spec.md에도 없던 구멍은 todo.md TODO로 남깁니다.
「같이 분석 → 논의 → 확정」 절차는 같고, 기준만 "받은 마크업 시안 + spec.md"입니다.

**코드기반 모드**는 목업·기획서가 없고 기존 구현 코드가 있는 경우로, BG가 planning·design을 켤지 물을 때 사용자가 코드를 자료 대용으로 쓰기로 한 경우에 적용합니다. 기획 체크리스트를 대상 코드에 대입하여 역산합니다.
「같이 분석 → 논의 → 확정」 절차는 같고, 기준만 "코드에서 읽어낸 현재 동작"입니다.

대상 코드는 메인이 읽지 않고, 이 모드 동안 코드 읽기 팀원(`workflow-code-reader`) 하나에 맡깁니다. 이미 떠 있으면 이어 씁니다([team-agent](../../../../contexts/team-agent.md) 규칙).
페이지마다 대상 코드 경로와 `checklist/`·[`../page-type/`](../page-type/) 폴더 경로를 넘기고, 페이지 유형과 체크리스트 항목별 현재 동작·근거 `파일:줄`만 돌려받아 page.md 초안을 씁니다. 논의 중 코드에 물을 것이 생기면 같은 팀원에게 다시 묻습니다.

#### 같이 분석

AI가 자료와 체크리스트를 기반으로 page.md 초안을 작성합니다:

1. 템플릿의 각 섹션을 자료에서 파악한 내용으로 채웁니다. 확신이 없는 항목은 `[?]`로 표기합니다.
2. 채팅에서 모호하거나 빠진 정의·`[?]` 항목·엣지케이스·(있으면) UX 대안을 구체적으로 나열합니다. **여기서 멈춥니다. 사용자 응답을 기다립니다.**

> **Figma 데이터 기록 범위**: [기록 시점 — Background 단계 보류](../../conventions/artifact/markup-spec.md#기록-시점--background-단계-보류) 참조.

#### 종합

모든 페이지 리뷰를 마친 후, 페이지 단위를 넘어 전체 플로우 관점에서 점검합니다.

대조와 TODO 모으기는 메인이 하지 않고 일회성 서브에이전트에 맡깁니다. 모든 page.md(`background/consumable/page-*.md`와 이미 PR로 옮겨진 `pr{N}/consumable/page.md`)와 global.md의 경로, [cross-page.md](./cross-page.md) 경로를 넘깁니다.
cross-page 체크리스트에서 걸린 항목, 아래 2의 공통화 후보(후보마다 쓰이는 페이지), 페이지마다 남은 TODO·`[?]` 항목만 돌려받습니다. 항목마다 근거 `파일:줄`과 그 원문 줄을 붙이게 해, 메인은 page.md를 다시 열지 않고 그 줄로 판단합니다.
design도 켜져 있으면 design 「종합」의 페이지 간 디자인 패턴 일관성 점검도 같은 서브에이전트에 넘깁니다.

1. cross-page에서 걸린 항목을 사용자에게 알립니다.
2. 공통화 검토 — 여러 페이지에서 쓰이는 컴포넌트·로직·UI 패턴은 사용자에게 알리고 global.md 공통 항목으로 올릴지 검토합니다. 한 페이지에서만 쓰이면 그 page.md의 「구현할 컴포넌트 목록」에 둡니다. 여러 페이지가 공유하는 레이아웃이 있으면 layout.md를 생성할지 확인합니다.
3. TODO 목록을 최종 정리합니다.

AI가 `global.md`의 나머지 칸(공통 컴포넌트·로직·레이아웃·엣지케이스·질문 목록)과, 생성하기로 한 경우 `layout.md`의 초안을 채웁니다. 사용자가 리뷰합니다.
