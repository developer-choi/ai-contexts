# 요구사항 리뷰

AI는 요구사항을 비판적으로 분석해 사용자에게 설명한다. 모호한 부분을 짚고, 엣지케이스를 먼저 꺼내며, 개선안을 제시한다. 단정하지 않고 장단점을 함께 설명한다.

## 목적

구현에 들어가기 전에 요구사항의 모호한 곳과 엣지케이스를 사용자와 함께 확정해, 다음 세션이 읽을 산출물로 남긴다.

## 입력 타입

argument로 플래그를 받는다.

- recruitment → [recruitment/guide.md](recruitment/guide.md)
- planning → [planning/guide.md](planning/guide.md)
- design → [design/guide.md](design/guide.md)

### 실행 순서

1. **recruitment** — 켜져 있으면 먼저 실행한다. 가이드의 자체 절차를 따르고 페이지 단위 루프는 쓰지 않는다.
2. **planning + design 루프** — 아래 「페이지 단위 루프」.

종합 단계는 모든 루프가 끝난 뒤 한 번만 한다.

플래그를 가리지 않고, 수집된 자료는 처음부터 다시 요청하지 않고 빠진 페이지·항목만 짚어 요청한다.

### 가이드 슬롯

planning·design 가이드가 정의하는 슬롯:

| 슬롯 | 페이지 단위 루프에서의 역할 |
|------|---------------------------|
| 준비 방식 | 루프 진입 전에 실행 |
| 입력 자료 | 루프 1단계에서 참조 |
| 체크리스트 | 루프 2단계에서 적용, 4단계에서 누락 대조 기준 |
| 산출물 | 루프 3~4단계에서 기록 |
| 분석 과정 | 루프 1~2단계에서 SKILL 본문보다 우선하고, 루프 종료 후 단계(종합)를 정의 |

---

## 확정 칸에 올리는 것

플래그를 가리지 않고, 이 리뷰가 쓰는 산출물 전부(page.md·global.md·todo.md·tech-constraints.md 등)의 「확정」 칸에는 사용자가 고른 것만 올린다. AI가 권장만 한 것은 확정 칸 밖에 권장안으로 둔다.

---

## 페이지 단위 루프

planning, design 중 하나라도 켜져 있으면, 플래그별 준비가 끝난 후 아래 사이클을 페이지마다 반복한다.

planning과 design이 모두 켜져 있으면, 한 페이지에서 planning 2~3단계를 마친 뒤 design 2~3단계를 이어 하고, 4단계는 두 쪽 체크리스트를 함께 놓고 한 번 한다.

### 1. 자료 참조

requirement 「자료 받기」가 `background/`에 수집한 자료를 참조한다.

### 2. 같이 분석

가이드의 체크리스트 슬롯을 기반으로 AI와 사용자가 같이 분석한다.

### 3. 논의

`/discussion`을 사용하여 사용자와 대화하며 미결 항목의 결론을 낸다.

- 확정된 내용 → 산출물에 기록
- 사용자가 판단할 수 없는 항목 → TODO로 분류
- 논의가 끝나지 않은 항목 → `[?]`로 표기

### 4. 확정

논의 결과를 산출물에 반영한다. 사용자가 수정한 말투나 표현은 다듬지 않는다.

사용자 확인 전에 page.md·global.md와 이 페이지에 적용한 체크리스트 파일(page-type 포함)의 경로를 일회성 서브에이전트(sonnet)에 넘겨, 빠진 항목(`파일:줄`·원문)만 돌려받는다.
page.md를 쓴 세션은 직접 대조하지 않는다.
지적마다 원본 자료(`background/`. 코드기반 모드면 코드 읽기 팀원에게 묻는다)로 해당 여부를 확인하고, 해당하지 않는 지적은 버린다.

사용자 확인을 받고 다음 페이지로 넘어간다.
