# 페이지 리뷰 step

받은 자료를 페이지 하나씩 열어, 기획과 디자인을 함께 따져 page.md·global.md에 남긴다.

## 준비

받은 자료와 이미 쓴 산출물로 답이 안 나온 페이지·항목만 짚어 요청한다.

1. 원본을 확인한다. 아래 둘은 원본이 다르다.
   - **마크업 시안 (개인 모드)**: `background/retained/mockup/`과 `background/retained/spec.md`(있으면)가 기획·디자인 원본이다.
   - **기존 코드 (코드 대용)**: `background/retained/code-target.md`가 있으면 그 파일이 적은 기존 구현 코드를 기획·디자인 자료 대신 쓰고, 체크리스트를 코드에 대입해 현재 동작을 역산한다.
     대상 코드는 메인이 읽지 않고, 리뷰 동안 코드 읽기 팀원(`workflow-code-reader`) 하나에 맡긴다. 이미 떠 있으면 이어 쓴다([team-agent](../../../contexts/team-agent.md#claude-code)).
2. 루프 대상 페이지와 페이지마다 페이지 유형·놓을 체크리스트를 수집된 자료에서 뽑아 사용자에게 확인받는다. 코드 대용이면 팀원에게서 대상 코드의 라우트·화면 목록과, 페이지마다 페이지 유형과 동작 로직·화면 마크업 중 무엇이 있는지를 받아 그것으로 뽑는다. 체크리스트는 아래에서 고른다.
   - 기획 — 화면이 어떻게 동작하나(URL·뒤로가기, 상태 전이, API, 에러·권한): [planning/checklist/](planning/checklist/)
   - 디자인 — 화면이 어떻게 생겼나(크기·줄바꿈, 로딩·빈 상태 화면, 반응형): [design/checklist/](design/checklist/). 컴포넌트 체크리스트는 그 페이지에서 새로 만들 컴포넌트(코드 대용이면 그 페이지의 컴포넌트 전부)에 놓는다.
   - 페이지 유형에 맞는 [page-type/](page-type/)
3. `/plan/background/consumable/global.md`와 루프 대상 페이지마다 `/plan/background/consumable/page-{영문 슬러그}.md`를 만든다. 담을 내용은 [output-template.md](output-template.md)다.
   page.md의 위치·이동은 [conventions/plan-folder.md](../conventions/plan-folder.md)를 따른다.
4. global.md의 개요·반응형 정책·비기능 요구사항을 채운다.

## 페이지 단위 루프

### 1. 자료 참조

requirement 「자료 받기」가 `background/`에 수집한 자료를 참조한다. figma URL·캡처의 저장 위치와 재요청은 [피그마 URL·캡처 캐싱](../conventions/plan-folder.md#피그마-url캡처-캐싱)을 따른다. 현재 리뷰 대상과 관련 없어 보이는 자료가 있으면 사용자에게 알린다.

### 2. 같이 분석

1. 이 페이지에 놓기로 한 체크리스트(page-type 포함)를 놓는다. 코드 대용이면 팀원에게 대상 코드 경로와 그 체크리스트 파일 경로를 넘기고, 체크리스트 항목별 현재 동작·근거 `파일:줄`만 돌려받는다.
2. 담을 내용을 자료에서 확인해 채우고, 자료에서 확인되지 않는 것은 미확정으로 표시해 둔다.
   - Figma 값은 [기록 시점](../conventions/artifact/markup-spec.md#기록-시점--background-단계-보류)대로 적거나 미룬다.
   - 마크업 시안이면 색·간격·크기·글꼴·배치 같은 시각 값은 시안에 둔다.
   - 채용과제 분석 산출물이 있으면 도메인을 모르는 기본 UI는 design-system.md에, 여러 화면에 걸친 데이터·규칙·에러는 domain-analysis.md에 적는다.
3. 채팅에 아래를 기획 → 디자인 순서로 묶어 나열한다. **여기서 멈추고 사용자 응답을 기다린다.**
   - 미확정으로 둔 것
   - 모호하거나 빠진 정의, 엣지케이스, (있으면) UX 대안
   - 자료끼리, 또는 이미 적힌 page.md와 자료가 어긋나는 곳

### 3. 논의

`/discussion`을 사용하여 사용자와 대화하며 미결 항목의 결론을 낸다.

- 확정된 내용 → 산출물에 기록
- 사용자가 판단할 수 없는 항목 → page.md에 기획자·디자이너에게 물을 질문으로
- 논의가 끝나지 않은 항목 → 미확정으로 둔다

### 4. 확정

논의 결과를 산출물에 반영하고, 사용자 확인 전에 빠진 항목을 대조한다.
page.md를 쓴 세션은 직접 대조하지 않는다. page.md·global.md(채용과제 분석 산출물이 있으면 그것도)와 이 페이지에 놓은 체크리스트의 경로(마크업 시안이면 시각 값은 시안에 둔다는 기준도)를 일회성 서브에이전트(sonnet)에 넘겨, 빠진 항목(`파일:줄`·원문)만 돌려받는다.
지적마다 원본(코드 대용이면 팀원)으로 확인해 해당하는 것만 반영하고, 사용자 확인을 받아 다음 페이지로 넘어간다.

## 종합

모든 페이지 루프가 끝난 뒤, 페이지 단위를 넘어 전체 플로우 관점에서 점검한다.

점검은 메인이 하지 않고 일회성 서브에이전트에 맡긴다. `node {{skill_dir}}/scripts/plan-folder.mjs requirement-files`가 낸 산출물 경로(기획 체크리스트를 놓았으면 [cross-page.md](planning/cross-page.md)도)를 넘겨, 페이지끼리 어긋난 곳, 공통화 후보, 남은 미확정·질문을 찾게 한다.
결과는 근거 `파일:줄`과 원문 줄을 붙여 돌려받아, 메인은 page.md를 다시 열지 않고 그 줄로 판단한다.

1. 결과를 사용자에게 알리고, 공통화 후보는 올릴지 정한다. 올리면 global.md(채용과제 분석 산출물이 다루는 것은 그 문서)에, 한 페이지에서만 쓰이면 그 page.md에 둔다. 여러 페이지가 공유하는 레이아웃이면 `/plan/background/consumable/layout.md`를 만들지 정한다.
2. 남은 미확정은 사용자와 정해 확정하거나 질문으로 돌리고, 여러 페이지에 걸친 질문은 global.md에 모은다.

AI가 global.md와 만들기로 한 layout.md의 빈 곳을 채운다. 사용자가 리뷰한다.
