# 스크롤 라이브러리 선택

## 문제

요구한 동작을 직접 구현할 수도 있었지만 두 가지 비용이 걸렸습니다.

1. 직접 구현하고 유지보수하는 비용
2. 직접 구현한 코드를 여러 브라우저와 기기에서 검증하는 비용

직접 개발했다면 시간이 오래 걸리고, 동료가 제 코드를 보고 유지보수하기도 어렵습니다.

배포 후에 특정 브라우저나 기기에서 문제가 생길 수도 있습니다.

하지만 라이브러리를 잘못 도입하면 유지보수 부담과 기기별 문제가 그대로 남습니다.

그래서 다음 기준으로 검토했습니다.

## 해결

### 도입 기준

1. 요구한 기능을 구현할 수 있어야 하고, 라이브러리의 **목적**이 그 기능과 **가까워야 합니다.**
2. 다운로드 수가 많은 것을 고릅니다. 신뢰성을 판단하는 지표로 다운로드 수를 개인적으로 채택하고 있습니다.
3. 앞의 두 기준을 만족하는 후보가 2개 이상이면, 용량·보일러플레이트 양·과한 기능 범위 같은 조건을 대입합니다.

### 후보와 판정

- 범용 애니메이션 라이브러리: 제공되는 API로 직접 구현해야 하는 코드가 많아 보여 반려했습니다.
- 설명만으로 목적이 맞는지 판단하기 어려운 것: 테스트 후보로 뒀습니다.
- 설명이 요구사항과 맞는 것: 테스트 후보로 뒀습니다.

남은 두 후보는 이렇게 갈랐습니다.

1. 유지보수 여부: 한쪽은 안정 버전이 유지보수 중단이고 다음 버전이 베타였습니다.
2. 주간 다운로드 수 차이: 2.8만과 330만이었기 때문에 여기서 비교를 중단했습니다. 만약 앞의 것이 훨씬 많았다면 유지보수 단점을 **상쇄할 만큼의 이유**가 있는지 찾으려고 했습니다.
3. 검증: 남은 후보를 실제로 테스트해 요구사항을 모두 만족하는 것을 확인하고 채택했습니다.
