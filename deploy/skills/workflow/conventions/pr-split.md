# PR 분할 — 확정 기준 + 분할 원칙 + 의존 서술

큰 작업을 여러 PR로 가르는 판단의 단일 출처. **일괄 분할 시점은 없다** — requirement에서 자료를 읽어나가며 확정 가능한 PR부터 하나씩 확정한다.

## 작업 크기 판단

커밋 3개 이하로 끝날 작업이면 사용자에게 분할 생략을 제안한다.

---

## PR 확정 기준 — "다른 문서를 더 안 봐도 확정 가능한가"

확정은 `node {{skill_dir}}/scripts/steps.mjs pr add --plan <plan> --name <이름> [--type <종류>] [--deps <선행 번호들>]`로 기록하고, 출력된 번호로 `<plan>/background/consumable/todo.md`에 PR 절을 붙인다.

아직 안 읽은 자료가 이 PR의 경계를 바꿀 수 없으면 확정하고 append한다. 그 PR은 곧바로 출발 후보가 된다.

### 확정 ≠ 출발 가능

둘은 따로 판정한다 — 경계 확정은 위 기준으로, 출발 가능은 「의존 — 판단거리 노출」로 가른다. 확정은 append-only로 쌓이고, 출발은 각 PR이 자기 선행이 풀릴 때 개별 발동한다.

---

## PR 종류

PR 종류의 정본은 [pr-types/](pr-types/)다 — 파일 하나가 종류 하나이고, 첫 줄에 경계와 적용 모드가 있다.
적용 모드에 이번 [모드](modes.md)가 든 종류를 PR로 만든다. 각 PR에 담을 항목은 그 PR의 plan이 정한다.
페이지 PR이 COMPONENTS PR을 의존으로 적을지는 BG가 사용자와 함께 판단한다(이미 있는 컴포넌트로 되는지 등을 본다).

---

## PR 분할 원칙

- **한 번에 하나의 PR, 하나의 구체적인 기능**만 다룬다.
- **기존 자산 변경 ≠ 신규 기능**: 한 PR이 기존 자산의 개명·이동·구조 변경(마이그레이션)과 새 기능 추가·확장을 동시에 하려 하면 두 PR로 가른다 — ① 마이그레이션 PR(동작 변화 없음, 개명·파일 이동·참조 갱신만), ② 기능 PR(그 위에 새 동작). 마이그레이션을 먼저.
- **의존성 순서**: 공통 모듈 → 개별 페이지
- **기술적 과제는 각 PR의 plan에서** — 분할 판단은 경계에만 집중

---

## 의존 — 판단거리 노출

AI는 "판단"이 아니라 "**판단거리 노출**"만 한다: 각 PR이 선행 PR에서 **무엇을 당겨 쓰는지 한 문장으로 적어** 사용자가 순차/병렬을 즉시 확정하게 한다.

- **무엇을 적나**: 선행에서 실제로 당겨 쓰는 것(함수·타입·컴포넌트·옮겨진 경로 등)을 구체적으로 적는다. 뒤 PR은 선행의 realize-plan 커밋(stub 또는 실행 결과)이 나오면 착수할 수 있다.

브랜치 base 결정도 이 서술을 판단거리로 쓴다 — 결정 자체는 사용자 확인 사항이다.

## 기획 점검 (TODO 식별)

PR을 확정할 때마다 `todo.md`의 미분류 절(PR 경계 확정 전에 쌓인 항목) 중 그 PR에 속하는 항목을 해당 PR 절의 맞는 하위 절로 재배치한다 — 어느 항목이 그 PR에 속하는지가 판단이라 이 옮기기는 손으로 한다.
그 외 각 PR별로 사용자에게 사전 확인이 필요한 새 TODO가 있는지 추가로 확인한다(아래 「PR별 TODO 등록처」에 넣는다).

---

## 산출물: `/plan/background/consumable/todo.md`

PR을 확정하면 아래 양식으로 PR 절을 `## 미분류` 절 바로 앞에 붙인다. `## 미분류`가 없으면 파일 끝에 붙이고, 그 뒤에 `## 미분류`와 `- 없음`을 둔다.

```
## PR {번호}. {이름}

### 의존

- PR {번호}. {이름} — {무엇이 있으면 착수 가능한지}

### 범위

- ...

### 참고 자료

- ...

### TODO

- ...
```

- 양식의 하위 절을 그 순서로 모두 둔다. 적을 것이 없는 절엔 `- 없음`을 둔다.
- 「의존」은 위 「의존 — 판단거리 노출」대로 적는다. 선행 번호는 `pr add --deps`에도 준다 — 출발 판정은 그쪽으로 한다.
- PR 종류는 `pr add --type`(값 = `pr-types/` 파일 이름)으로 기록한다.
- 선행·종류·이름을 바꾸면 `pr set --plan <plan> --n <N> [--deps …] [--type …] [--name …]`과 md 쪽(「의존」 줄·헤딩)을 함께 고친다.

### PR별 TODO 등록처

`todo.md`에 그 PR 절이 남아 있으면 그 절의 「TODO」, plan이 소비해 절이 없으면 `pr{N}/persistent/overview.md`의 `## TODO`에 적는다. 어느 PR이 할지 아직 정해지지 않았으면 `## 미분류`에 적는다. 소비된 PR에 등록할 때 그 PR이 이미 verify를 마쳤으면 사용자에게 알린다.

범위·참고 자료도 같은 판정으로 자리를 정하되, PR 절이 남아 있으면 그 절의 「범위」·「참고 자료」에 적는다. plan이 소비한 PR의 항목이면 범위는 그 PR의 TODO로 위처럼 적고, 참고 자료는 `pr{N}/persistent/reference.md`에 적는다.

### 번호와 이름

**번호는 확정 순서다.** `pr add`가 매기고, 폴더·세션·워크트리 이름이 이 번호를 쓴다.

**이름은 사람이 읽는 보조다.** 식별자가 아니라서 나중에 바꿔도 폴더·세션 이름에 영향이 없다. 페이지 PR은 페이지명을 그대로 쓴다.
