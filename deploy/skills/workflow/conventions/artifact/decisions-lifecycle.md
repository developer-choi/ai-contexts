# decisions.md 컨벤션

`/plan/pr{N}/persistent/decisions.md`는 나중에 리뷰어·후임자·면접관이 "여기 왜 이렇게 했어요?"라고 물을 때 답할 근거를 남긴다 — 무엇을 골랐고, 무엇을 버렸고, 왜인지.

## 포함·제외 기준

그 "왜"를 물을 만한 결정만 적는다 — 사용자가 고르거나 고친 결정, 다른 합리적인 후보를 두고 고른 결정. 애매하면 사용자에게 적을지 묻는다.

- "우려했으나 확인해 보니 문제없음"으로 닫힌 걱정은 결정이 아니다 — 적지 않는다.
- PR 분할·범위 변경은 그 PR의 TODO로 적는다 ([PR별 TODO 등록처](../pr-split.md#pr별-todo-등록처)).
- 사용자의 단발 발화, 특히 체념하거나 즉흥으로 정하는 어조의 발화로 항목을 추가하기 전에 명시 확인을 받는다.

## 적는 법

결정마다 `## 결정 N` 아래에 채택안·기각한 대안·근거를 적는다. 사용자가 정한 결정은 LLM 초안, 차수별 사용자 발화와 LLM 보고를 그대로 인용한다.

코드에서 역산 가능한 표면값(커밋 SHA·파일 경로·폴더 구조 등)은 근거에 박지 않는다. 코드 앵커가 꼭 필요하면 이름 수준(어떤 모듈·어떤 결정)에서 그친다.

## 머리 안내문

파일 맨 위에 아래 안내문을 둔다.

```markdown
> 구현·리뷰 도중에는 고치지 않는다 — 그사이 나온 결정은 verify 「decisions.md 최신화」에서 한 번에 반영한다. 이 문서와 PR 본문이 다르면 PR 본문이 우선이다.
```

## 갱신 (구현·리뷰 후)

구현·리뷰에서 새로 생긴 결정을 포함 기준대로 적는다. plan에서 정했다가 바꾸거나 버린 결정도 무엇으로 바뀌었는지와 함께 적는다.
