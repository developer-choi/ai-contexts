# 결론만 가져오면 되는 큰 작업은 별도 세션으로 빼자고 묻는다

이 세션의 컨텍스트는 이 세션의 산출물을 만드는 데 쓴다. 이 세션에 필요한 것은 결론뿐이고 거기 닿는 과정(읽은 문서, 재현 앱 코드, 측정 로그)은 다시 쓰지 않는 작업을 아래 방아쇠대로 곧 시작하려 하면, 시작하기 전에 새 창에서 따로 끝내고 결론만 가져올지 사용자에게 묻는다. 빼는 결정은 사용자가 한다. 이 제안은 단계가 끝난 뒤 다음 세션을 여는 안내와 별개다.

그 작업이 이 세션의 본래 일에 속한 결정이어도, 사용자가 직접 시킨 일이어도 묻는다. 서브에이전트로 조사하라·직접 검증하라는 지시·규칙도 수단을 정한 것이지 이 물음을 건너뛰라는 뜻이 아니다 — 옆 세션에서 재현·조사해 가져온 결론도 직접 검증한 것이다. 사용자는 이 정책을 기억해 두고 먼저 빼 달라고 하지 않는다.

**방아쇠 — 곧 하려는 행동으로 판단한다.** "길어질 것 같다"는 느낌이 아니라, 다음 응답에서 하려는 일이 아래 중 하나면 그 일을 **시작하기 전에** 묻는다. 비교표·조사를 먼저 내고 묻지 않는다.

| 형 | 방아쇠 |
|---|---|
| 결정형 | 선택지 3개 이상을 비교하려 한다 / 결정 하나의 근거를 대려고 외부 문서·라이브러리 소스를 여러 곳 읽으려 한다(WebFetch·WebSearch·소스 내려받기로 직접 읽든 서브에이전트에 맡기든 같다 — 보고와 이어지는 검토가 이 세션에 쌓인다) / 가설을 가리려고 재현용 앱·페이지를 새로 만들려 한다 / 결론이 이 세션 산출물 여러 개(다른 PR의 interface 포함)를 바꾼다 |
| 버그형 | 원인 가설이 2번 연달아 틀렸고, 3번째 가설을 세우려 한다 |

묻는 말: "이 {조사·재현·버그 추적}은 이 세션에 결론만 있으면 되는데 {방아쇠 근거 한 줄}. 별도 세션에서 끝내고 결론만 가져오실래요? 여기서 이어가도 됩니다."

**묻지 않는 자리**:
- 과정 자체가 이 세션의 산출물인 일 — 요구사항 정리·PR 확정·분할, 자기 PR의 설계 문서·stub 작성, 자기 PR 구현
- 선택지 2개짜리이고 바뀌는 산출물이 한 곳인 결정
- 가설이 1번만 틀린 버그 — 그 자리에서 다음 가설을 잇는다

**수락하면** 이 세션은 그 작업을 하지 않고, 아래 인수인계 문서와 옆 세션에 붙여 넣을 프롬프트를 낸다. 옆 세션은 정식 세션 종류가 아니다 — `/workflow`를 부르지 않고 새 창에 프롬프트만 들고 간다. 옆 세션의 결론 문서와 재사용할 검증 파일(재현 페이지·측정 스크립트)은 넘긴 세션의 `plan/…/consumable/`(재현 페이지·측정 스크립트처럼 여러 step이 다시 쓰면 `retained/`)에 남기게 하고, 프롬프트에 그 경로를 박는다. 거절하면 그대로 이어간다.

프롬프트는 먼저 읽을 파일 경로 목록(인수인계 문서, 요구사항·관련 산출물)으로 시작한다. 이어서 결론 문서를 남길 `plan/` 경로, 끝나면 원래 세션에 돌아와 전할 한 줄(채택안 또는 원인)을 넣는다.

**인수인계 문서 양식** — 넘긴 세션의 `plan/…/consumable/`에 쓴다.

버그형:
- 증상 — 사용자 표현 그대로
- 이미 확인한 것 — 다시 재지 말 것 (측정값, 재현 도구 경로)
- 가설 (확정 아님) — 틀린 가설과 근거, 남은 가설
- 함정 — 도구 때문에 이상한 값이 나오는 자리
- 지금 코드 상태 — 워크트리·브랜치·커밋, 미커밋 실험값
- 아직 안 정한 것
- 남은 단계
- 쓸 수 있는 도구

결정형: 위에서 「가설」「함정」 대신 「후보와 판단 기준」(후보 목록, 사용자가 말한 기준, 결론이 바꿀 산출물 목록)을 쓴다.

가설에는 「확정 아님」을 달고, 절 제목에 판정(「별개」「무관」)을 박지 않는다.
