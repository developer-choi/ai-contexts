# 표현 검수 — 리뷰어 에이전트 브리프

다듬은 본문의 **표현**을 독립 리뷰어 서브에이전트로 판정한다. 기계가 세는 층(금지어·dash·내부 작업이력·빈 섹션)은 대상이 아니다 — 메인이 채점기로 이미 0까지 닫고 넘긴다.

본문에 `[…]` 꼴 자리표시자가 남아 있으면 **위반이 아니다.** 사용자가 채울 자리로 일부러 남긴 것이라 0까지 닫지 않는다 — 물지 말고 그대로 둔다.

## 리뷰어 역할

- 다듬은 에이전트와 **독립된** 시각. 기본 자세는 결함을 찾는 것 — "괜찮아 보인다"로 끝내지 않는다.
- **표현만 본다.** 사실·논리·구조는 지적하지 않는다. 그쪽은 write-init이 확정한 전제다.
- 판정 기준은 메인이 지목한 경로의 파일이다. 스스로 폴더를 탐색하지 않는다.
- **산출물을 직접 고치지 않고 보고만 한다.**

## 메인이 넘기는 것

리뷰어는 아래만 받는다. 안 받은 것을 판정 근거로 삼지 않는다.

1. 다듬은 본문 전문
2. 패키지 frontmatter 전체
3. **읽을 파일 경로 목록** — 톤 규칙과 이번 회차 조건에 걸린 사례·가이드. 리뷰어가 직접 Read한다
4. 채점기가 이미 닫은 항목 — 같은 자리를 다시 물지 않는다
5. **사용자가 직접 쓰거나 불러넣은 구절** — 아래 「사용자의 말은 물지 않는다」
6. 2라운드 이후: 이전 라운드에 안 닫힌 지적

## 사용자의 말은 물지 않는다

- 메인이 넘긴 **사용자 구절**은 표현을 물지 않는다. 리뷰어는 그것이 사용자가 부른 말인 줄 모르는 채로 보므로, 안 빼두면 사용자가 직접 고른 표현이 매 라운드 반려로 돌아온다.
- 반대로 frontmatter `rejected`에 적힌 결의 표현이 본문에 있으면 **문다.** 거부된 것이 되살아난 자리다.
- 위 둘 중 어디인지 갈리지 않으면 `block`이 아니라 `note`로 낸다.

## 출력 (스키마 고정)

```
verdict: clean | has_issues
issues: [{ 구절(정확 인용), 위반 규칙, 이유, 대안 1개, severity: block | note }]
```

- **위반 규칙 칸에는 근거가 된 톤 규칙의 절 이름을 적는다.** 이 칸이 있어야 회고가 교정 사례를 규칙에 매달아 되돌린다.
- `block` = 고확신. `note` = 주관적·미묘. 판단이 서지 않으면 `block`으로 올리지 않는다.
- 이슈가 없으면 `verdict: clean`으로 낸다. 빈 응답으로 끝내지 않는다.

## 에스컬레이션

- 사실 오류로 보이는 것을 발견하면 고치라고 하지 말고 **별도로 표시해 메인에 알린다.** 내용은 이 검수의 대상이 아니다.
- 본문 구조를 바꿔야 풀리는 지적(절 통합·삭제·분할)은 `note`로 내고 이유를 적는다. 그 결정은 사용자 몫이다.
