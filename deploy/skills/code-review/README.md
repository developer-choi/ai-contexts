# Code Review

코드 변경을 살펴보고 고칠 거리를 목록으로 뽑아주는 스킬입니다. 고칠지 말지는 이 스킬을 부른 쪽(사람 또는 다른 스킬)이 정합니다.

## 동기

코드 리뷰를 하다 보면 "이 이름은 이렇게 짓기로 했잖아요" 같은 지적을 사람마다, PR마다 반복하게 됩니다.

그래서 자주 나오는 지적은 코딩 규칙 문서로 한 번 정리해 두고, AI가 그 문서를 직접 읽어 가며 리뷰하도록 만들었습니다. 규칙에 없는 문제는 AI가 경험 많은 리뷰어의 시선으로 따로 살핍니다.

## 전체 흐름

변경 의도 읽기 → 규칙 문서 고르기 → 검사자들이 대조 → 단정 못 한 지적은 돌려서 확인 → 이슈 목록

## 리뷰 방식

먼저 리뷰할 코드와 그 코드가 무엇을 하려던 것인지(PR 설명, 변경 의도)를 읽습니다. 그리고 그 코드에 해당하는 코딩 규칙 문서를 골라 와 대조합니다. 변경이 React 컴포넌트나 합성 패턴에 걸리면 Vercel이 배포한 베스트 프랙티스 스킬의 관점도 함께 적용합니다.

예제 코드 모음(MP)의 문서는 규칙 문장만이 아니라 예제 코드의 모양까지 대조합니다. 예제가 이미 보여 주는 자리에서 예제에 없는 함수를 따로 만들었거나, 다른 라이브러리 API로 연결했거나, 한 곳에 둘 상태를 따로 나눴으면 동작이 같아도 짚습니다.

「사용자가 정한 것이라 다르다」는 차이는 결정 기록에 그대로 적힌 것만 넘어갑니다. 검사자가 단정하지 못한 지적(「문제가 생길 수 있다」, 「판단할 수 없다」 등)은 실제로 돌려 확인한 뒤에 받거나 버립니다.

구현 파일을 리뷰할 때는 그에 딸린 테스트도 함께 가져와 살핍니다. 코드만 보고 테스트를 안 보면 둘 사이의 문제를 놓치기 때문입니다.

리뷰 범위는 변경 작성자가 실제로 손댄 코드입니다(새 규칙에 맞춰 정렬할 때는 리뷰 대상으로 지정한 기존 파일 전체입니다).

결과 맨 앞에는 이번 리뷰에서 실제로 읽은 규칙 문서 목록이 옵니다. 찾아낸 문제는 심각도(꼭 고쳐야 하는 것, 사소한 것, 제안)로 나눠 정리하고, 규칙에 근거한 지적이면 어느 규칙 문서의 몇 번째 줄을 어겼는지까지 적습니다.
규칙 문서와 다른 근거가 부딪히는 지적, 결정 기록을 근거로 넘어간 차이, 확인하지 못한 지적은 따로 모아 보여 줍니다. 부딪히는 지적은 어느 쪽을 따를지 사람이 정합니다.

## 쓰임새

### 코드 점검 (`--mode advanced`, 기본값)

사람이 직접 부를 때도, 작업 흐름 안에서 만든 코드를 다른 스킬이 점검할 때도 이 모드로 돕니다. 코딩 규칙을 영역별로 나눠 여러 검사자가 동시에 봅니다.
더 무거운 검사자 둘이 따로 붙어, 하나는 직접 만든 것을 대신할 공식 수단(내장 API·표준 라이브러리)이 있는지를, 다른 하나는 규칙 바깥의 깊은 문제를 봅니다. 작업 흐름에서 부를 때는 코드를 만든 쪽이 자기 코드를 직접 검사하지 않도록, 만드는 역할과 검사하는 역할을 나눕니다.

### 새 규칙에 맞춰 정렬 (`--mode only-standards`)

규칙을 새로 바꿨을 때, 기존 코드에서 그 규칙 위반만 모아 줍니다. 바꾼 규칙 문서를 `--coding-standards`로 넘기면 그 문서만으로 확인하고, 넘기지 않으면 규칙 문서를 스스로 골라 확인합니다. 자유 리뷰와 외부 베스트 프랙티스 스킬 관점은 범위를 흐리므로 빼고 돌립니다.
