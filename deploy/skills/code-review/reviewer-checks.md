# 리뷰어 전수 대조

## MP 예시와 코드 모양 대조

MP 베스트 프랙티스 파일과 거기서 따라간 `코드:` 경로 문서는 규칙 문장뿐 아니라 예시 코드도 diff에 대본다. 의도·동작이 같은지가 아니라 코드 모양이 같은지를 본다.

1. 예시의 함수마다 diff에서 같은 역할을 하는 코드를 찾는다
2. 짝마다 둘의 본문을 줄 단위로 나란히 놓고, 아래 종류마다 diff 쪽에만 있는 것을 적는다. 없으면 「없음」이라 적는다 — 적지 않은 종류는 보지 않은 것으로 친다
   - 함수: 예시에 없는 함수 선언(지역 헬퍼·래퍼 포함)
   - 연결: 예시와 다른 라이브러리 API로 한 연결
   - 상태: 예시가 한 곳에 두는 상태를 따로 든 저장소
3. 짝 × 종류 결과를 표로 싣고, 「없음」이 아닌 칸마다 severity를 붙여 이슈로 낸다
   - 다른 칸과 묶지 않는다
   - 그 모양이 필요해 보여도 면제 근거가 아니다 — 필요한지는 사용자가 정한다

예시가 다루지 않는 업무 로직(도메인 값 변환 등)은 이 대조의 대상이 아니다.

이슈마다 예시 쪽과 diff 쪽을 각각 `파일 경로:줄 번호`로 적어 나란히 놓고, 처리 방향으로 「예시 모양으로 바꾼다」와 「그 모양이 꼭 필요하면 사용자 승인을 받아 진행하고 MP 예시 추가 후보로 남긴다」를 함께 적는다.

## 추가된 주석 전수 대조

주석을 허용 목록으로 묶는 규칙을 대조하는 리뷰어는 지시문에 받은 주석 추출 완성 명령을 돌려 새로 추가된 주석 후보를 전부 뽑는다.
스크립트가 낸 표의 판정 칸을 행마다 채운다 — 허용 목록의 어느 항목인지, 어디에도 안 들면 「위반」, 주석이 아니면 「주석 아님」. 근거인 허용 목록의 파일 경로:줄은 표 위에 한 번 적는다.

- 주석 규칙 위반은 이 표의 「위반」 행마다 severity를 붙여 이슈로 낸다. 눈에 띈 주석 몇 개로 이슈를 쓰면 다른 형식(`/** */` 등)이 통째로 빠진다
- 사용 안내·API 설명 JSDoc처럼 기존 코드에 같은 모양의 선례가 있어도 허용 근거가 아니다
