# Rule Ablation Bench 특화 체크리스트

`deploy/rules/`, `deploy/contexts/coding-standards/` 등 **지침/규칙 문서**에서 "이 규칙을 없애도 되는가"를 재는 ablation 벤치의 점검 항목.

## 시나리오 시드 — 규칙 rationale에서 직접 추출

### 앞선 eval-set부터 찾는다

`bench-ablation.mjs`는 돌 때마다 eval-set에서 변형을 뺀 사본을 `%TEMP%\prompt-review-evals\<rule_id>.json`에 남긴다.
`rule_id`는 `<스킬·문서 이름>-<절 이름>`으로 지어, 다른 문서의 같은 이름 절과 겹치지 않고 파일명만으로 찾게 한다.
eval-set을 꾸리기 전에 그 폴더에서 그 이름의 파일을 찾는다.

- 있으면: 채점 축(`grader`·시나리오별 축)과 `inheritance_signatures`가 지금 대상 문안과 맞는지 대조해 낡은 것을 고친 뒤, 이번 변형만 끼워 쓴다
- 없으면: 아래 절차대로 새로 만든다

### 절차

- 규칙 본문의 rationale·예시·"이 규칙이 방어하려는 상황" 맥락을 먼저 추출한다
  - rationale이 짧으면 commit log, 관련 backlog, 과거 사용자 대화에서 추가 단서를 찾는다
- 추출한 맥락을 positive 시나리오 시드로 사용한다
- 일반 예시로 대체 금지. 규칙이 방어하려는 구체 상황이 아닌 프롬프트로 측정하면 결과는 "일반 문체·행동 경향"만 보여주고 **규칙의 효과는 측정하지 않는다**
- **채점 정답 선존재 차단**: 시나리오의 채점 정답이 워커가 읽을 수 있는 환경(타겟 파일·cwd)에 이미 있으면 ZERO가 "읽고 확인"만으로 통과해 ablation 변별력을 잃는다. 정답이 환경에 박혀있지 않은(빈/오답) 타겟으로 시나리오를 구성한다.

측정 대상이 시스템 프롬프트가 아니라 워커가 열 파일이면, 비교군별 변형본 폴더는 `{{skill_dir}}/benching/scripts/build-arms.mjs`가 만든다. 손으로 만들지 않는다.

## ZERO negative control + 환경 상속 탐지

ablation 벤치는 ZERO(규칙 제거) variant를 포함한다.

### 환경 상속 의심 탐지

ZERO 비교군 워커가 제거한 규칙의 특징 어휘·구절을 응답에서 재사용하면 환경 상속 의심 신호다. 그 어휘를 eval-set `inheritance_signatures`에 넣으면 하네스가 갈리지 않은 행(델타 없음·안 갈림·바닥)을 「보류(상속 의심)」로 돌린다.

### 상속 경로 (구체 메커니즘)

일반 세션·서브에이전트 워커는 `~/.claude/rules/`와 cwd `CLAUDE.md`를 자동 로드해 ZERO가 성립하지 않는다.
배포된 규칙은 `{{skill_dir}}/benching/scripts/bench-ablation.mjs`로 잰다 — 격리 방식·인자·eval-set 스키마는 그 파일이 정본이다.
배포본을 비교군마다 갈아끼우지 않는다(다른 세션까지 오염).

### 단일 측정만으로는 확정 불가

"ZERO = A"(A는 원본 비교군)는 여러 원인 중 어느 것인지 단일 측정으로 구분할 수 없다:
- 환경 상속 (워커가 자동 로드한 규칙 본문)
- 모델 baseline 내재화 (규칙 없이도 동일 행동하는 모델)
- 시나리오 부족 (규칙이 방어하는 맥락을 시나리오가 재현 못함, 또는 위반을 유발할 압박 부재)

의심되면 판정 보류하고 방법을 바꾼다.

## 한 패스로 닫는다 — 안 갈린 것은 다시 재지 않는다

회차를 거듭하며 애매한 후보만 잘라 다시 재는 대신, 한 번 돌려 확실한 것만 판정하고 닫는다. 축마다 판정은 `bench-ablation.mjs` 요약 표의 「판정」 열이 찍고, 여기서는 처리만 정한다.

| 판정 | 처리 |
|---|---|
| 갈림 | 규칙이 값을 한다. 남긴다 |
| 델타 없음 | 삭제 후보로 올린다 — 확정은 위 「단일 측정만으로는 확정 불가」의 원인 배제를 통과한 뒤 |
| 바닥(양 비교군 다 실패) | 규칙이 있어도 실패해 잰 것이 없다. 삭제 근거로 쓰지 않고 대상을 그대로 둔다 — 시나리오나 규칙 문안을 의심할 자리다 |
| 안 갈림 | 적어두고 대상을 그대로 둔다 |
| 보류(재측정)·보류(중단)·보류(반복 미달)·보류(상속 의심) | 판정하지 않는다. 안 잰 것이지 델타가 없는 것이 아니다. 사유는 결과 보고에 적는다 |

- 「안 갈림」을 풀려고 반복을 올리거나 시나리오를 바꿔 다시 재지 않는다. 지울 근거가 없으면 남기는 것이 결론이다.
- 예외: 되돌리기 비싼 판정(문서·절을 통째로 지우는 것, 공개 API 변경)이 그 축 하나에 걸려 있으면 그 축만 반복을 올린다.

## 판정 증거 기준

| 판정 | 요구 증거 |
|------|-----------|
| 완전 제거 | 규칙 rationale 맥락(positive) + 대조 맥락(규칙 반대 행동이 자연스러운 상황) 둘 다 시나리오로 확보. 양쪽에서 ZERO = A. 환경 상속 의심 없음 |
| 압축 | rationale 맥락에서 ZERO ≠ A (규칙 고유 가치 확인) + 압축본에서 A와 동일 행동 |
| 유지 | 압축본이 rationale 맥락에서 A와 달라짐 |

## 압축 변형 트리거 재검증

압축본은 원본보다 트리거 어휘가 짧아져 매칭 범위가 **확장**될 수 있다. 압축 채택은 rationale 맥락 변별만으로 끝내지 않고 contrast 시나리오로 정밀도를 재측정한다.

## 사용자가 반례를 낼 때

판정을 바로 뒤집지도 고수하지도 않는다. 「단일 측정만으로는 확정 불가」의 원인에 모델 업데이트(측정 시점과 반례 시점의 모델 차이)를 더해 어느 쪽인지 가릴 측정을 제안하고, 가려질 때까지 판정을 보류한다. 모델 업데이트가 원인이면 "현재 모델 기준 불필요"로 판정하고 다음 모델 변경 때 다시 잰다.
