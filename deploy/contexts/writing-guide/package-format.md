# package-format

글쓰기 패키지(frontmatter + 본문 단일 .md)의 형식 SSOT입니다. 패키지를 만드는 쪽도 다듬는 쪽도 형식 정의를 본문으로 재인용하지 않고 이 파일을 포인터로 가리킵니다.

"언제·어떻게 채우는가"는 각 스킬이 소유합니다. 여기서는 필드와 그 의미만 정합니다.

```markdown
---
type: pr-body
subtype: recruitment
kind: 성능 개선
audience: 채용담당자
audience_knowledge: 무한스크롤 도메인 모름, 코드베이스 처음
purpose: 성능 최적화 어필
key_message: 무한스크롤 도입으로 초기 렌더 시간 60% 단축
length_target: 주요 섹션 3-4개, 섹션당 3-4문단
rendering_env: markdown
rejected:
  - '"심혈을 기울인" (자기 산출물 과장)'
  - '"측정 환경 상세" 절 (지나친 세부라 사용자가 뺌)'
user_phrases:
  - '"스크롤 끝에서 다음 페이지를 미리 부른다" (사용자 발화: "스크롤 끝에서 다음 페이지를 미리 부른다고 써줘")'
refs:
  git_log: a1b2c3..d4e5f6
  related_files:
    - src/components/InfiniteScroll/
    - docs/perf.md
---

# 무한스크롤 도입으로 초기 렌더 시간 60% 단축

## 스크롤 끝 감지를 IntersectionObserver로 바꾼 이유
...
```

어느 필드가 필수인지는 `deploy/hooks/check-package-frontmatter.mjs`가 저장 시점에 거부로 판정합니다. 선택 필드는 불확실하면 비우거나 `미상`으로 둡니다.

- `type`·`subtype`: 이 글의 종류. 허용 어휘와 subtype 필수 여부는 패키지를 만드는 스킬의 입력 규격이 단일 출처라, 여기서 다시 나열하지 않습니다.
- `kind`: 이 글의 성격(기능·버그·리팩터처럼 같은 type 안에서 글 모양이 갈리는 것)으로, 같은 성격 승인본을 고르는 이름입니다. 선택 필드입니다.
    - `subtype`과 축이 다릅니다 — `subtype`은 누가 누구에게 쓰는 글인가(채용용 PR, 검토자 코멘트)를 정해 템플릿·가이드와 승인본 폴더를 고르고, `kind`는 무엇을 바꾼 글인가를 정해 그 폴더 안에서 승인본 한 편을 고릅니다. 채용용 PR도 버그 수정일 수 있어 둘은 따로 적습니다.
    - 이름은 승인본 파일 첫 줄 `# <성격>`과 같은 말로 씁니다(`types/<type>/[<subtype>/]approved/`).
- `key_message`: 이 글에서 독자가 가져갈 한 문장. 저장 시점에 새로 짓지 않고 합의된 문장을 그대로 옮깁니다.
- `length_target`: 본문 분량 목표를 자유 서술로 적습니다(예: `주요 섹션 3-4개, 섹션당 3-4문단`). 적혀 있으면 템플릿의 default보다 우선합니다.
- `rendering_env`: `markdown` (default, 생략 시 가정) | `plain-text` | `rich-text`. 본문이 출력될 환경입니다. `plain-text`(이력서 입력 필드, 텍스트 폼 등)면 백틱·코드펜스·헤딩 마크 등 마크다운 문법을 본문에 사용하지 않습니다.
- `rejected`: 사용자가 이 문서에서 거부한 것을 `"원문" (거부 사유)` 한 줄씩 담습니다.
    - 낱말·문구뿐 아니라 사용자가 뺀 절·다루지 않기로 한 내용도 담고, 그때는 원문 자리에 절이면 `"절 제목" 절`로, 내용이면 그 내용을 짧게 적습니다.
    - 원문만 피하고 같은 사유로 거부될 다른 표현을 새로 짓는 것을 막기 위해 사유까지 적습니다. 다듬는 쪽이 말하는 「같은 결」은 이 사유가 같다는 뜻입니다.
    - **사유에 정해진 어휘는 없습니다** — 채점기 분류 이름(`score.mjs --rules`)은 낱말 단위 톤 규칙이라 지나친 세부·사실과 다름·말투가 아님 같은 실제 거부 사유를 대부분 담지 못합니다. 맞는 분류가 있으면 그 이름을 써도 됩니다.
    - **한계** — 사용자가 말로 거부하지 않고 본문을 직접 고쳐버리는 암묵 거부는 이 필드가 잡지 못합니다.
- `user_phrases`: 리뷰어가 표현을 물지 않을 구절을 `"구절 원문" (출처)` 한 줄씩 담습니다. 사용자가 직접 쓰거나 불러넣은 구절과, 확정된 글(게시본·승인받은 단위)이 이미 쓰는 용어입니다. 출처는 그 발화 원문, 사용자가 편집한 자리, 확정된 글의 인용입니다. AI가 대화나 승인 전 초안에서 되풀이한 말은 몇 번 나왔든 넣지 않습니다. 구절 원문은 본문에 들어간 글자 그대로 적습니다 — 채점기가 공백·굵게·기울임만 걷고 본문과 대조합니다.
- `refs`: 이 글의 근거 자료(커밋 범위·관련 파일·PR·조사 문서, 시리즈로 쓰는 글이면 앞서 확정한 글)가 있는 자리를 담습니다.

frontmatter는 다듬는 쪽이 대화 히스토리 없이도 출발할 수 있게 해주는 핵심 인터페이스입니다.
