# pr-body 가이드

## PR 제목

패키지 본문의 H1이 PR 제목이다. 게시할 때 H1은 PR 제목 칸에, frontmatter와 H1을 뺀 나머지는 PR 본문에 넣는다.

제목은 합의한 `key_message`를 한 줄 길이로 줄이거나 늘려 짓는다. 줄일 때는 `key_message`의 주장을 남기고, 그 주장을 받치는 방법·근거부터 덜어낸다.

- 확인한 결과가 있으면 한 일이 아니라 드러난 것을 담는다
- 명사형 보고체로 끝낸다
- 끝에 마침표를 찍지 않는다
- `feat:` 같은 conventional commit 접두사를 붙이지 않는다
- 공백 포함 60자 이하

## 절

절은 주제마다 하나씩 세운다. 주제는 이 PR에서 내린 결정 하나, 또는 만든 동작 하나다. 절 제목은 그 주제가 말하는 내용으로 짓는다. 템플릿의 재료 이름이나 「배경」·「요약」처럼 어느 PR에나 붙는 이름은 제목으로 쓰지 않는다.

## 넣지 않는 것

- 커밋 목록이나 바꾼 파일·컴포넌트 나열. GitHub PR 화면이 이미 보여준다.
- 일반 PR이면 이 PR 밖을 가리키는 것과 작업한 흔적. 다른 PR 번호, 커밋 해시, 브랜치명, 백로그 번호, 작업 세션 링크, 생성 도구 표기, 작업 대화에서 나온 말("사용자 결정" 같은 것)이 여기 든다. 리뷰어와 나중에 레포를 둘러보는 사람은 그 맥락을 볼 수 없다.
- 일반 PR이면 디테일. 리뷰어는 바뀐 값 하나하나까지 읽지 않는다.
