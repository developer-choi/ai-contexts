# 결정문 작성 가이드

여러 구현 방법을 비교하고 선택 근거를 남기는 기술적 의사결정 문서(`type: decision`)의 작성·검토 규칙입니다.

## 비교 구조

- **방법을 둘 이상 견줍니다.**
- **견준 방법마다 장점과 단점을 밝힙니다.**
- **결론에 선택 이유와 비선택 이유가 모두 드러납니다.** 형식은 자유(단락·서브섹션·bullet). 결론 섹션만 단독으로 읽어도 "왜 다른 방법이 탈락했는지" 파악되어야 합니다.
- **장단점·탈락 사유는 사용자가 채웁니다.** AI는 임의로 채우지 않고, 빠진 것은 사용자에게 받습니다.

## 핵심 문장

고른 방법과 핵심 근거를 한 문장에 담습니다. 예:

- "기본 케이스에서 `<label>`로 감싸기 채택 — JS 0줄 선언적 위임이 `<div>` + `handleClick`보다 기본값 비용이 낮음"
- "복합 케이스에서도 `<label>` + `htmlFor` 채택 — 선언적 쌍 vs 명령적 JS 비대칭이 유지되어 label 쪽이 여전히 덜 번거로움"
