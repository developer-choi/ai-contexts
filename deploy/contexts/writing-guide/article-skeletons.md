# article-skeletons

기술 글(`type: article`)의 **상황 → 골격** 사례집입니다. 골격을 세우기 전에 "이번 글은 어느 상황인가"를 고르면 검증된 서사구조가 따라 나옵니다.

핵심 메시지에서 논리적으로 파생된 목차가 곧 읽히는 골격은 아닙니다. 왜·언제·어떻게로 나눈 교과서 목차는 논리는 맞아도 독자가 따라갈 이야기가 없습니다. 이 사례집은 실제로 통과한 서사를 모아 그 간극을 메웁니다.

**형제 문서가 먼저입니다.** 이번 글이 들어갈 시리즈에 이미 글이 있으면 그 글이 논지를 펴는 방식을 먼저 읽고 따릅니다. 여기 사례는 형제 문서가 없거나 그 방식이 이번 상황에 안 맞을 때 꺼냅니다. 사례집과 다른 구조로 갈 거면 그 이유를 사용자에게 먼저 말합니다.

새 글에서 잘 나온 구조는 여기에 상황과 함께 누적합니다.

## 상황: 같은 결과를 내는 방법이 여러 개일 때

**골격: 최악 → 차악 → 최선 순차 개선**

독자는 이미 최악의 방법을 쓰고 있을 가능성이 높습니다. 각 단계의 잃는 것이 다음 단계로 내려가는 동기가 되어서, "왜 굳이 최선까지 가야 하는지"가 저절로 설명됩니다. 결론부터 던지면 독자는 자기가 쓰던 방법이 왜 나쁜지 모른 채 받아들여야 합니다.

구성 요소:

- 목표 절 끝에 **최악 코드**를 배치하고 "왜 손해인지 차례차례 풀어보겠습니다"로 넘깁니다.
- 절마다 **같은 형식으로 닫습니다** — 「얻는 것과 잃는 것」 두 줄. 앞 절에서 잃은 것이 다음 절로 내려가는 동기가 됩니다.
- **하나의 예시**를 처음부터 끝까지 끌고 갑니다. 각 단계에서 같은 버그가 잡히느냐 마느냐로 차이를 잽니다.
- 마지막에 **오답 사례**를 둡니다. 사다리를 잘 내려왔어도 애초에 전제가 틀렸으면 소용없다는 반전입니다.

```
## 이 단계의 목표        (최악 코드 배치 + 전개 예고)
## [최악 방법]           + 얻는 것과 잃는 것
## [차악 방법]           + 얻는 것과 잃는 것
## [최선 방법]           + 얻는 것과 잃는 것
## [애초에 필요했나]      (오답 사례)
## 결론
```

이 구조를 쓴 실물 두 편(둘 다 MP `docs/guides/testing/`):

- `test-levels.md` — E2E(최악) → integration → unit(최선). 이메일 유효성검증 하나를 끝까지 끌고 갑니다. 오답 사례는 icecream cone.
- `how-to-mock.md` — 함수 통째(최악) → fetch → MSW(최선). 댓글 작성 요청 하나를 끝까지 끌고 갑니다. 오답 사례는 모킹할 필요 없는 순수 함수를 모킹한 경우.

**반려된 골격** (같은 주제, 1차 시도):

```
## 모킹하면 무엇을 잃나요        (왜 아껴야 하나)
## 그래도 팔아야 할 때가 있습니다  (언제 하나)
## 팔기로 했어도 덜 팔 수 있습니다  (어떻게 하나)
```

핵심 메시지에서 정확히 파생됐지만 "잘 안 읽힌다"로 반려됐습니다. 형제 문서(`test-levels.md`)가 이미 쓰던 사다리 서사를 읽지 않고 만든 목차였습니다.
