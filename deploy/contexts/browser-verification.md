# 브라우저를 조작할 때

## 넘기기 전에 끝까지 해 본다

콘솔 설정도 화면 대조·동작 확인도 브라우저로 직접 한다. 사용자에게 넘기는 것은 아래뿐이다.

- 로그인·결제·CAPTCHA
- 확정 버튼 누르기, 비밀 값 복사 (아래 두 절)
- 사람 눈으로 판정할 것 — 화면을 띄워 두고 판정만 넘긴다

도구가 막히면 「막히는 자리」부터 해 본다. 그래도 안 되면 해 본 것을 적어 넘긴다.

## 콘솔·대시보드 폼을 채울 때

확정 직전까지 채우고, 채운 값을 보여 준 뒤 확정 버튼만 넘긴다.

- **확정 버튼이 여러 개면 대상마다 탭을 나눠 저장 직전 상태로 둔다.**
- **사용자가 누른 뒤 페이지를 새로고침해 저장된 값을 읽는다.**

## 사용자가 비밀 값을 옮겨 줘야 할 때

AI가 보면 안 되는 값(DB 주소·API 키 등)을 사용자가 콘솔에서 로컬로 옮겨 줘야 하면, 넘기기 전에 받을 자리와 찾을 자리를 열어 둔다. 사용자에게는 복사·붙여넣기·저장만 남긴다. 값 복사를 넘기는 것은 AI가 비밀을 보지 않으려고 일부러 하는 것이다.

- **받을 파일**: git이 무시하는 경로인지 확인하고, 아니면 무시되는 경로로 바꾼다. 거기에 `KEY=` 빈칸 줄을 두고(있는 파일이면 덮지 않고 그 줄만 덧붙인다) 편집기(Windows는 메모장)로 연다.
- **찾을 페이지**: 값이 있는 콘솔 페이지를 크롬으로 열고 그 변수 이름으로 필터해 둔다.
- **값은 보지 않는다**: 값이 드러나는 화면·클립보드·파일 내용을 읽지 않는다. 페이지는 필터까지만 해 두고, 파일은 그 키에 값이 채워졌는지만 확인한다.
- **치우기**: 이번 작업에만 쓰려고 만든 파일이면 그 값을 쓰는 작업이 끝난 뒤 지운다.

예: 운영 DB 마이그레이션에 Vercel의 `DATABASE_URL_UNPOOLED`가 필요하다 → `.env.production.local`에 `DATABASE_URL_UNPOOLED=`를 만들어 메모장으로 열고, Vercel 프로젝트 Settings → Environment Variables를 `DATABASE_URL_UNPOOLED`로 필터해 둔 채 "Vercel 탭에서 값 복사 → 메모장에 붙여넣기 → Ctrl+S"만 요청한다.

## 띄우는 명령을 실제로 돌리는 것부터가 검증이다

파일을 만들어놓고 제어 가능한 탭에서만 열면, 사용자가 실제로 그것을 여는 경로(예약작업·기본 브라우저 연결)가 사는지는 안 드러난다. 띄우는 명령을 먼저 그대로 돌리고, 그다음 같은 파일을 조작 가능한 탭에서 연다.

## 막히는 자리

아래는 실제로 막혀 본 자리다. 모르고 들어가면 벽에서 되돌아 나오게 된다.

- **`file://`은 확장이 막는다.** 로컬 서버로 띄워야 열린다. `localhost`는 보안 컨텍스트라 클립보드 동작 확인에는 오히려 정확하다.
- **페이지 안에서 클립보드를 읽으면 권한 게이트에 걸려 렌더러가 멎는다.** 복사 버튼을 실제로 누르고 OS 클립보드를 읽으면 사용자가 붙여넣을 값 그 자체가 나온다.
- **요소 참조로 누른 클릭이 핸들러를 못 깨우는 일이 있다.** 좌표 클릭으로 바꾼다.
- **클릭 좌표는 CSS px가 아니라 스크린샷 좌표로 잡는다.** 둘의 폭이 달라 엉뚱한 요소가 눌린다. 클릭 결과가 이상하면 앱 버그로 보기 전에 좌표부터 의심한다.
- **스크린샷이 계속 시간 초과되거나 페이지가 하이드레이션되지 않으면 새 탭에 같은 주소를 연다.** 숨은 탭·iframe에서 잘 나고, 같은 탭에서 창 크기를 바꿔서는 안 풀린다. 사용자에게 창을 꺼내 달라고 하기 전에 한다.
- **페이지가 스크립트에서 나오는지, 스킬 본문의 템플릿을 그때 렌더하는지 먼저 가른다.** 후자는 넘길 스펙이 없어 템플릿을 더미 값으로 채워야 한다.
- **JS 대화상자(alert·confirm·prompt)를 띄우면 이후 제어가 통째로 멎는다.** 그 버튼을 눌러야 하면 먼저 사용자에게 알린다.

## 멈출 지점을 어떻게 찾나

산출물을 확인하다 저장까지 돌릴 때, 저장이 진짜 데이터를 건드리는 지점은 대개 파일 하나 안에 있다. 저장 스크립트가 검증을 쓰기보다 앞에 두면 거부 갈래는 오염 없이 끝까지 돌아가므로, 어디서 쓰기가 시작되는지 보고 선을 긋는다 — 저장 단계 전체를 통째로 건너뛰면 안 돌려봐도 될 것까지 안 돌린 게 된다.
