# 문장 다듬기

필요한 내용을 가장 짧고 오해 없이 적었는지 본다. 이 내용이 이 독자에게 필요한지는 [본문에 무엇을 남기나](what-to-keep.md)가 가른다.

## 군더더기 낱말은 지운다

의미 없는 부사·접속어(`기본적으로`, `사실상`, `즉`, `또한`, `이러한`, `~의 경우`, `~를 통해`), 동어 반복(`반드시 필수로`, `미리 사전에`), 늘어진 명사구(`~에 대한 검증을 수행한다` → `~를 검증한다`)는 삭제·압축한다.

## 약한 어휘는 지우고 강조 라벨은 붙이지 않는다

"항상 X 하라"를 문서에 반영할 때:
- 조건부 게이트(`(선택)`, `필요하면`, `필요시`)를 제거해 평범한 단언 절차문으로 만든다
- `(필수)`, `항상`, `반드시`, `묻지 않는다` 같은 강조 라벨은 덧붙이지 않는다

산출물 정의(step-4 표 등)에서 "여부와 무관하게", "필요시", "옵션", "선택적으로" 같은 약한 어휘를 쓰면, 그 산출물을 소비하는 다음 단계가 "쓸 수도 안 쓸 수도"로 인식한다. 시간 압박이나 자체 검열이 들어왔을 때 자연스럽게 줄이는 흐름이 나온다.

이전 사고: `test-cases.md` 정의에 "테스트코드 작성 여부와 무관하게"가 있어 PLAN이 implementation.md의 단위테스트를 "옵션 3건"으로 줄였고 IMPL이 0건 채택했다.

리뷰 시 산출물 정의 본문에 위 표현이 보이면 디폴트(작성 필수/금지)를 명시하도록 보강 제안한다.

표 칸 값으로 쓰인 "필수/금지"와 `[CRITICAL]`처럼 뜻이 정의된 마커는 값이라 이 절의 대상이 아니다.

## 개수를 본문에 박지 않는다

전역 git pre-commit 훅(`scripts/hooks/check-count-hardcoding.mjs`)이 커밋이 건드린 프롬프트 md를 통째로 훑어 개수 하드코딩을 감지해 경고한다(차단 아님). 이번에 고친 줄이 아니어도 같은 파일이면 그 커밋에서 함께 정리한다 — **"따로 다룰까요"로 사용자에게 넘기지 않는다.** 훅이 뜨면 아래 기준으로 줄마다 판단한다. 문자열만 봐서는 안 갈리는 부분이라 훅이 못 대신하고, 그대로 둘 줄이 대부분이더라도 판정 자체는 그 자리에서 끝난다:

- 늘어날 목록의 개수를 가리키면 일반화 표현으로 교체 (`5문항` → `자가검증 문항`, `3개 단계` → `각 단계`). 앞에 열거된 집합을 가리키면 위치 참조로 (`세 영역` → `위 영역들`)
- 설계상 고정된 쌍·닫힌 열거(바로 뒤에 전부 나열됨)면 그대로 둔다
- 글로벌 룰 「구체적인 개수를 본문에 하드코딩하지 않는다」(AC CLAUDE.md)의 자동화 절차. 훅이 못 잡는 것(명사 없이 단독으로 쓰인 수량어 등)은 여전히 스스로 살핀다
- 같은 훅이 스텝 번호 범위 호명(`Step 1~3`)도 별도 문구로 짚는다. 처방이 다르다 — 일반화가 아니라 역할 이름(「본 절차」)으로 바꾼다. 단일 번호(`Step 2`)와 가리키는 문서 이름이 다른 줄에 있는 경우는 훅이 못 잡으므로 스스로 살핀다

## 사용자 말투를 옮기지 않는다

사용자가 직접 한 발화(특히 1인칭·구어·맥락 의존 표현)를 SKILL.md에 그대로 옮기지 않는다. SKILL.md는 공개 문서이고 다른 세션의 AI가 읽는 글이라, 작성 시점의 사용자 개인 사정·구어가 그대로 들어가면 의미가 깨진다.

- 예: "난 자세히 안 봐" → "사용자가 본문을 매번 검수하지 않을 수 있다는 전제에서"
- 예: "그냥 잘 재현만 되게" → "재현 가능성이 본 절차의 목표"
- 일반화 후 박는다. 사용자 개인 발화를 그대로 옮기는 것은 금지
