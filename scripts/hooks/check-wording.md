# check-wording.mjs 사용법

sync가 이 파일을 `~/.ai-contexts/check-wording.mjs`로(옆의 `blocked-expressions.json`도 함께) 복사하고 전역 git pre-commit 훅으로 등록한다. 사람·AI가 손으로 실행하는 것은 `--report`다.

## 호출

- `node ~/.ai-contexts/check-wording.mjs --report <md 또는 폴더 경로>` — 커밋 없이 묻는다
  - 폴더면 그 아래 `.md`마다(`node_modules`·`.git` 제외) 본다
  - 작업 트리의 내용을 보고, 프롬프트 문서 범위(`/skills/`·`/rules/`·`/contexts/`·`meta/guides/`·`CLAUDE|AGENTS|GEMINI.md`) 밖의 파일이어도 본다. 판정은 그 파일이 있는 레포 기준이다
  - AC에서는 `node scripts/hooks/check-wording.mjs --report <경로>`도 같다
- `node ~/.ai-contexts/check-wording.mjs` — 인자 없음. pre-commit 훅으로 도는 모드다. 현재 레포에 스테이징된 프롬프트 md(삭제·내용 그대로인 이름 바꿈 제외)를 통째로 본다

## 출력

- 범주마다 `[강조 라벨 의심]`·`[약한 어휘 의심]`·`[군더더기 낱말 의심]`·`[영어 먼저 한글 풀이 헤딩 의심]`·`[금지 표현 의심]`·`[긴 한 줄 문단 의심 — 200자 이상]` 헤딩 아래 `<파일>:<줄>: <줄 내용>  (<걸린 말>)`. 범주마다 20건까지 낸다
- `[CRITICAL]`은 AC가 아닌 레포에서만 강조 라벨로 잡는다
- `[금지 표현 의심]`은 걸린 줄 아래에 행마다의 「대신 쓸 말」을 찍는다. 목록 파일이 옆에 없으면 이 범주만 건너뛴다
- `판단:`으로 시작하는 줄은 걸린 줄을 어떻게 고칠지, 그대로 둘지 가르는 기준이다
- 커밋 모드에서 긴 줄 밖의 범주가 걸리면 「이 커밋에서 함께 정리한다」 안내가 붙는다. 커밋하는 쪽이 줄마다 판정해 고칠 것은 고치고, 둔 것은 건수와 사유를 보고에 적는다
- `--report`는 파일마다 적중이 없으면 `<경로> — 적중 없음.`, 다 본 뒤 `한계:` 줄(못 잡는 꼴)을 낸다

## exit code

- 커밋 모드는 늘 0이다. 내부 오류도 `[낱말 검사 훅 내부 오류, 건너뜀]`만 찍고 0
- `--report` 뒤에 경로가 없으면 사유와 이 문서 위치를 stderr에 내고 1. 파일이 없으면 `파일이 없다: <절대경로>`, 폴더 아래 md가 없으면 `md가 없다: <절대경로>`와 1
