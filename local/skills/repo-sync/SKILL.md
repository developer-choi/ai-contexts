# Repo Sync

## 목적

내가 자주 쓰는 프로젝트들을 origin과 동기화한다. 컴퓨터 2대 이상에서 작업을 이어갈 때 미푸시 작업 유실을 막는 게 목적이다.

## 실행

AC에서 `node scripts/repo-sync.mjs`.

순회 범위·보호 브랜치 판정·ahead/behind 분기·다른 보호 브랜치 ff·결과 표는 그 스크립트가 안다. git을 직접 불러 순회하지 않는다 — 한 레포를 건너뛰거나 한 분기를 잘못 읽어도 표에는 정상으로 적히고, 조용히 빠지는 그것이 이 스킬이 막으려던 유실이다.

정하는 것은 둘이다.

### WIP 커밋 메시지

`wip-needed`로 나온 레포는 스크립트가 손대지 않고 넘긴다 — 무슨 작업을 하던 중이었는지는 사람 쪽만 안다.

레포마다 변경 목록과 diff를 보고 그 작업의 성격을 담은 메시지를 정한 뒤, 스크립트가 함께 내주는 `--wip … --message …`를 부른다. 커밋이 거부되면 메시지를 고쳐 다시 부른다.

### 사용자 조치 필요

표에 `blocked`·`failed`·`dirty`·`stash-conflict`·`ff 불가` 행이 있으면 표 아래에 절을 만들어 레포별 추천 액션을 짧게 안내한다. 스크립트는 그런 행이 몇 건인지까지만 내고 무엇을 하라고는 안 한다.
