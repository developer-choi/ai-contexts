# TypeScript Advanced Patterns

## 안전한 타입 단언 (`satisfies` vs `as`)

### 원칙: `satisfies` 우선 사용
타입을 확정하면서도 원래 값의 구체적인 정보(Literal Type 등)를 유지하고 싶을 때, `as` 대신 `satisfies`를 우선적으로 검토해야 합니다.

**❌ Bad (Type Assertion)**
- `as`를 쓰면 컴파일러가 타입을 맹신하게 되어, 잘못된 속성이나 오타를 잡아내지 못할 수 있음.

**✅ Good (satisfies)**
- 타입 호환성은 체크하되, 실제 값의 타입 정보를 유지함.

### `as`가 남는 자리
`as`가 남는 자리는 `satisfies`로 같은 목적을 이룰 수 없는 이유가 있어야 한다. 그 이유가 코드에서 보이지 않으면 사용자에게 의도를 확인한다.

## `as unknown as` 금지

`as unknown as T` 이중 단언은 사용하지 않는다. 타입 시스템이 두 타입의 호환을 거부한다는 신호를 강제로 무력화해 런타임 오류의 직접 원인이 된다. 타입 정의 수정·런타임 검증 같은 대안이 모두 막혔다고 판단되면, 코드에 넣기 전에 사용자에게 상황과 시도한 대안을 보고하고 승인을 받는다.
