# README 작성 가이드

톤은 common.md를 따르되, 1인칭 서술("제가 일하는 방식을", "제가 실무에서")을 사용합니다.

## 성격

- 최근 커밋에서 무엇이 바뀌었는지(diff)가 아니라 프로젝트의 현재 모습을 기준으로 씁니다. README는 변경 이력을 모아두는 곳이 아닙니다.
- 자랑하거나 파는 문서가 아닙니다. 무엇을 만들었고 무엇을 하는지 담백하게 소개합니다. 어필 포인트를 앞세우지 않습니다.

## 전체 흐름 개요

여러 단계나 구성요소로 이뤄진 프로젝트·스킬의 README에는 전체 그림을 한눈에 보여주는 개요를 둡니다. 이 한 토막만 읽어도 "무엇을 넣으면 무엇이 나오는지" 감이 와야 합니다.

- 입력에서 결과까지를 흐름으로 보여줍니다. 단순하면 화살표 한 줄로(예: 기획서 → 배경 파악 → 설계 → 구현 → PR), 분기·병렬이 있으면 위에서 아래로 흐르는 세로 그림으로 갈라지는 구조를 드러냅니다. 자동 생성 막대 차트(간트 등)는 진행 시간만 보일 뿐 이 구조가 드러나지 않으므로 쓰지 않습니다.
- 한 그림에 모든 단계·분기·반복을 욱여넣지 않습니다. 핵심 병렬 구조만 남기고 나머지는 본문으로 풉니다. 예시:

```
배경 파악 · PR 분할
  │
  ├──→ 화면 마크업  (PR 작업과 동시에 진행)
  │
  ▼
PR마다  설계 → 구현·리뷰 → 본문 작성
  │
  ▼
완성된 PR
```
- 흐름은 그 프로젝트가 흐름을 정의한 문서(스킬이면 SKILL.md 또는 SKILL.md가 가리키는 곳)에서 도출하되 내부 표기째로 베끼지 않습니다.

## 스킬 README인 경우

- SKILL.md가 정의한 내용을 독자가 알아볼 수 있게 옮깁니다. 1차 소스는 SKILL.md입니다.
- 만든 동기를 문제와 해결 구조로 담습니다. SKILL.md에 목표·동기가 적혀 있으면 그것을 도입부 중심에 두고 「어떤 문제가 있어서 → 이렇게 푼다」 순으로 풉니다. 목표를 여러 기능 중 하나처럼 뒤로 흩뜨리지 않습니다. 독자가 '왜 이게 필요한가'를 먼저 이해해야 나머지가 읽힙니다.
