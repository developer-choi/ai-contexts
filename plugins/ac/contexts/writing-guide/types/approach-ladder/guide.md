# 접근 사다리 작성 가이드

같은 결과를 내는 방법이 여럿일 때, 최악 → 차악 → 최선으로 옮겨 가며 어느 방법을 언제 고르는지 판단 기준을 보이는 기술 글(`type: approach-ladder`)의 작성 규칙입니다.

## 쓸 때 챙길 것

- 하나의 예시를 전 절이 공유합니다. 절마다 예시가 바뀌면 독자가 차이를 잴 기준을 잃습니다.
- 각 단계 절은 같은 꼴로 닫습니다(예: 「얻는 것과 잃는 것」).
- 코드 블록은 실행 가능한 최소 단위로 씁니다. 생략은 `...`이 아니라 주석으로 무엇이 생략됐는지 밝힙니다.

## 핵심 문장

어느 방법을 어디까지 쓰는지에 대한 판단 한 문장입니다. 예: "모킹은 확신과 맞바꾸는 거래라, 모킹하려는 이유를 없앨 만큼만 교체한다"
