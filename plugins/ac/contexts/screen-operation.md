# 화면을 대신 조작할 때

웹 화면은 크롬 확장으로, 안드로이드 폰의 앱 화면은 adb로 조작한다. 막히는 자리 절은 지금 사용하는 수단의 것만 보고, 나머지 절은 수단과 상관없이 따른다.

## 넘기기 전에 끝까지 해 본다

콘솔 설정도 화면 대조·동작 확인도 브라우저·폰으로 직접 한다. 사용자에게 넘기는 것은 아래뿐이다.

- 로그인·결제·CAPTCHA, 지문·계좌 비밀번호 같은 본인 인증
- 확정 버튼 누르기, 비밀 값 복사 (아래 두 절)
- 사람 눈으로 판정할 것. 화면을 띄워 두고 판정만 넘긴다

도구가 막히면 그 수단의 막히는 자리 절부터 해 본다. 그래도 안 되면 해 본 것을 적어 넘긴다.

## 확정 직전까지 채운다

콘솔·대시보드 폼, 앱의 주문·입력 화면은 확정 직전까지 채우고, 채운 값을 보여 준 뒤 확정 버튼만 넘긴다. 돈이 나가는 버튼은 사용자가 시켜도 누르지 않는다.

- **확정 버튼이 여러 개면 대상마다 탭을 나눠 저장 직전 상태로 둔다.**
- **사용자가 누른 뒤 페이지를 새로고침해 저장된 값을 읽는다.**
- **채운 값이 그대로 적용되지 못하게 막는 표시가 화면에 있으면 넘길 때 같이 알린다.**

## 사용자가 비밀 값을 옮겨 줘야 할 때

AI가 보면 안 되는 값(DB 주소·API 키 등)을 사용자가 콘솔에서 로컬로 옮겨 줘야 하면, 넘기기 전에 받을 자리와 찾을 자리를 열어 두어 사용자에게는 복사·붙여넣기·저장만 남긴다. 값 복사를 넘기는 이유는 AI가 비밀을 보지 않기 위해서다.

- **받을 파일**: git이 무시하는 경로인지 확인하고, 아니면 무시되는 경로로 바꾼다. 거기에 `KEY=` 빈칸 줄을 두고(있는 파일이면 덮지 않고 그 줄만 덧붙인다) 편집기(Windows는 메모장)로 연다.
- **찾을 페이지**: 값이 있는 콘솔 페이지를 크롬으로 열고 그 변수 이름으로 필터해 둔다.
- **값은 보지 않는다**: 값이 드러나는 화면·클립보드·파일 내용을 읽지 않는다. 페이지는 필터까지만 해 두고, 파일은 그 키에 값이 채워졌는지만 확인한다.
- **치우기**: 이번 작업에만 쓰려고 만든 파일이면 그 값을 쓰는 작업이 끝난 뒤 지운다.

## 띄우는 명령을 실제로 돌리는 것부터가 검증이다

파일을 만들어놓고 제어 가능한 탭에서만 열면, 사용자가 실제로 그것을 여는 경로(예약작업·기본 브라우저 연결)가 사는지는 안 드러난다. 띄우는 명령을 먼저 그대로 돌리고, 그다음 같은 파일을 조작 가능한 탭에서 연다.

## 여러 에이전트에 나눠 동시에 확인할 때

확인할 시나리오가 여럿이면 에이전트에 나눠 동시에 돌리되, 에이전트끼리 로그인 상태·데이터·서버·탭에서 충돌하지 않게 한다. 폰 한 대는 화면 하나를 공유하니 나누지 않고 한 에이전트가 차례로 돌린다.

## 멈출 지점을 어떻게 찾나

산출물을 확인하다 저장까지 돌릴 때, 저장이 진짜 데이터를 건드리는 지점은 대개 파일 하나 안에 있다. 저장 스크립트가 검증을 쓰기보다 앞에 두면 거부되는 종류의 요청은 오염 없이 끝까지 돌아가므로, 어디서 쓰기가 시작되는지 보고 선을 긋는다.
저장 단계 전체를 통째로 건너뛰면 안 돌려봐도 될 것까지 안 돌린 게 된다.

## 막히는 자리: 크롬

아래는 실제로 막혀 본 자리다. 모르고 들어가면 벽에서 되돌아 나오게 된다.

- **`file://`은 확장이 막는다.** 로컬 서버로 띄워야 열린다. `localhost`는 보안 컨텍스트라 클립보드 동작 확인에는 오히려 정확하다.
- **페이지 안에서 클립보드를 읽으면 권한 요청 창에 걸려 렌더러가 멎는다.** 복사 버튼을 실제로 누르고 OS 클립보드를 읽으면 사용자가 붙여넣을 값 그 자체가 나온다.
- **조작하는 탭은 대개 숨은 탭이라 클릭 뒤 화면이 안 바뀐다.** 크롬 창 맨 앞에는 사용자의 탭이 있어서 조작하는 탭은 `visibilityState=hidden`이고 `requestAnimationFrame`이 돌지 않는다.
  그래서 눌러도 창이 안 열린 채 멈춰 있다가 스크린샷을 찍으면 그제야 열린다.
  클릭·키 입력 뒤에는 스크린샷을 한 번 찍고 나서 DOM을 읽고, 안 열렸다고 판정하기 전에도 먼저 스크린샷을 찍는다.
- **요소 참조로 누른 클릭이 핸들러를 못 깨우는 일이 있다.** 좌표 클릭으로 바꾼다.
- **클릭 좌표는 CSS px가 아니라 스크린샷 좌표로 잡는다.** 둘의 폭이 달라 엉뚱한 요소가 눌린다. 클릭 결과가 이상하면 앱 버그로 보기 전에 좌표부터 의심한다.
- **스크린샷이 계속 시간 초과되거나 페이지가 하이드레이션되지 않으면 새 탭에 같은 주소를 연다.** 숨은 탭·iframe에서 잘 나고, 같은 탭에서 창 크기를 바꿔서는 안 풀린다. 사용자에게 창을 꺼내 달라고 하기 전에 한다.
- **페이지가 스크립트에서 나오는지, 스킬 본문의 템플릿을 그때 렌더하는지 먼저 가른다.** 후자는 넘길 스펙이 없어 템플릿을 더미 값으로 채워야 한다.
- **JS 대화상자(alert·confirm·prompt)를 띄우면 이후 제어가 통째로 멎는다.** 그 버튼을 눌러야 하면 먼저 사용자에게 알린다.

## 막히는 자리: 안드로이드(adb)

화면은 스크린샷과 뷰 트리 XML로 읽는다.
XML은 `adb shell uiautomator dump <폰 경로>`가 폰 안에 저장하니 그 경로를 `adb pull`로 가져온다. 노드마다 `text`·`content-desc`·`bounds`가 있어 누를 좌표를 정확히 잡을 수 있다.

- **adb가 PATH에 없을 수 있다.** Windows는 사용자 폴더의 `AppData\Local\Android\Sdk\platform-tools\adb.exe`를 먼저 찾아본다.
- **화면 전환 직후의 덤프는 이전 화면을 줄 때가 있다.** 전환 뒤에는 스크린샷을 먼저 찍어 화면이 바뀌었는지 보고, 덤프는 그다음에 믿는다.
- **덤프가 안 되는 앱이 있다.** `ERROR: could not get idle state`나 `null root node returned`가 나고 파일이 안 생긴다. 그런 앱은 스크린샷을 보고 좌표를 잡는다.
- **스크린샷은 줄어서 보일 수 있다.** 보이는 이미지 폭이 폰 해상도(`adb shell wm size`)보다 작으면 보이는 좌표에 (폰 해상도 폭 ÷ 보이는 이미지 폭)을 곱해 `adb shell input tap`에 넣는다.
- **스크린샷이 통째로 검으면 몇 초 뒤 다시 찍는다.** 그래도 검으면 지문 인증 같은 보안 화면이라 읽을 수 없으니 사용자에게 넘긴다.
- **`input text`로는 한글이 안 들어간다.** 공백은 `%s`로 넣는다. 칸을 비울 때는 `adb shell input keyevent 123`(커서를 끝으로)을 보낸 뒤 `adb shell input keyevent 67`(지우기)을 글자 수만큼 보낸다.
- **앱이 자체 숫자 키패드를 띄우면 그 키를 좌표로 누른다.** 비밀번호 입력 키패드는 누르지 않고 넘긴다.
