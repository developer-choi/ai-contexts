# 공통 패턴

> 라이브러리 종류와 무관하게 간소화 시 유지하거나 제거하는 패턴

## 유지 패턴

### Component

- **ARIA 접근성**: `role`, `aria-*` 속성 유지
- **키보드 내비게이션**: 키보드 인터랙션 유지
- **기본 UI 동작**: 열기/닫기, 포커스 트래핑, ESC 닫기 등 핵심 인터랙션 유지
- **컴포넌트 합성 구조**: 부모-자식 관계의 핵심 패턴 유지

---

### 기능 제거 시 — required vs polish 해부

기능/서브시스템을 제거할 때 통째로 지우지 않는다. 서브시스템을 두 부분으로 가른다:

- **필수(required)**: 이걸 지우면 **유지하기로 한 다른 기능이 깨진다** → 유지. 이유 주석은 [「주석 전면 금지」](~/.claude/contexts/coding-standards/rules/personal/general.md#주석-전면-금지)의 허용 목록에 들 때만 단다
- **폴리시(polish)**: 없어도 유지 기능이 정상 동작 → 제거

판정 질문: **"이 코드를 지우면 KEEP하기로 한 기능이 동작을 멈추는가?"** Yes면 필수다.

---

## 삭제 패턴

### 주변 기능/서브시스템 제거

> ⚠️ 이 절의 나머지 삭제 패턴은 반복 등장하는 개별 제거 패턴이다. 이 항목은 그보다 큰 단위(서브시스템 단위)의 **기능(capability) 제거**다 — 둘 다 간소화 계획에 포함된다. 개별 패턴만 적용하고 끝내지 않는다.

**무엇을**: 컴포넌트의 핵심 개념 학습에 필요 없는 **사용자 대면 기능·서브시스템 전체**

**어디서**: 중첩/Sub 변형, 장식성 하위 컴포넌트(인디케이터 등), 타이밍/딜레이·방향 애니메이션 폴리시, 보조 레이아웃 모드 등

**왜 불필요한가**:

- **학습 목적**: 핵심 흐름은 그 기능 없이도 완전히 학습 가능. 기능이 핵심 경로에 분기를 추가해 흐름을 흐림
- **판정**: SKILL.md 학습 범위 테스트(특히 delta-over-sibling) 적용

**삭제 대상**:

- 그 기능의 컴포넌트(들), 전용 props, context 슬라이스, 그리고 그 기능이 형제 컴포넌트들에 관통시킨 모든 `if (기능)` 분기

**⚠️ 부분 해부 필수**: 위 「기능 제거 시 — required vs polish 해부」를 따른다.

### Disable/Enable Props 제거

**무엇을**: 기능을 켜고 끄는 boolean props (disable*)

**왜 불필요한가**:

- **학습 목적**:
    - 대부분 기본값(false) 사용 → 항상 켜진 상태
    - 예외 케이스는 학습에 불필요

**삭제 대상**:
- `disable*` 계열 props → 분기 제거, 기능을 항상 켜진 상태로 고정
- 조건부 활성화 로직

---

### 복잡한 Ref 처리 제거

**무엇을**: 여러 ref를 병합하거나 전달하는 복잡한 로직

**왜 불필요한가**:

- **학습 목적**:
    - ref 병합은 고급 주제
    - 단순한 ref 하나로도 컴포넌트 이해 가능
- **대안**: ref 하나만 사용

**삭제 대상**:
- `useForkRef(ref1, ref2)` → 하나의 ref만 사용
- 복잡한 ref 병합 로직
- React.cloneElement로 ref 주입

---

### 브라우저 호환성 코드 제거

**무엇을**: 구형 브라우저를 지원하기 위한 코드

**왜 불필요한가**:

- **학습 목적**:
    - 현대 브라우저만 타겟
    - 호환성 코드는 레거시 지원용으로 학습과 무관
    - 표준 API 사용이 더 명확함

**삭제 대상**:
- IE11 대응 코드
- 구버전 브라우저 대응 (vendor prefix 등)
- Polyfill
- Feature detection 조건문

---

### Interval/Polling 로직 제거

**무엇을**: 주기적으로 상태를 체크하는 코드

**왜 불필요한가**:

- **학습 목적**:
    - 이벤트 기반 처리가 더 직관적
    - Interval은 브라우저 버그 우회용 (학습과 무관)

**삭제 대상**:
- `setInterval()`로 주기적 상태 체크
- interval ID 관리 코드

---

### 특수 케이스 처리 제거

**무엇을**: 특정 요소나 상황을 위한 예외 처리

**왜 불필요한가**:

- **학습 목적**:
    - 일반적인 케이스만 이해해도 충분
    - 특수 케이스는 고급 주제
    - 80% 상황에서 동작하면 학습 목적으로 충분

**삭제 대상**:
- 특정 타입별 예외 처리
- Edge case 방어 코드

**예시**:
```javascript
// ❌ 삭제 대상
if (event.target.tagName === 'INPUT' && event.target.type === 'radio') {
  const radioGroup = doc.querySelectorAll(`input[name="${event.target.name}"]`);
  // 라디오 그룹 내 포커스 이동 로직 (20줄)...
}
if (isSentinelNode(event.target)) {
  handleFocusSentinel(event);
}

// ✅ 단순화 결과
// 일반 Tab 순서에 따른 포커스 이동만 처리
```

### 복잡한 알고리즘 단순화

**무엇을**: 복잡한 계산이나 정렬 로직

**왜 불필요한가**:

- **학습 목적**:
    - 알고리즘 자체가 학습 주제가 아님
    - 단순한 방법으로도 대부분 정상 동작

**삭제 대상**:
- 복잡한 정렬/탐색 알고리즘 → 단순한 대안으로 대체

---

### 유틸리티 함수 제거

**무엇을**: 재사용을 위한 helper 함수들

**왜 불필요한가**:

- **학습 목적**:
    - 한 곳에서만 쓰면 인라인이 더 명확
    - "무엇을 하는가"가 바로 보임
- **원칙**: YAGNI - 실제로 재사용할 때만 함수화

**삭제 대상**:
- 한 번만 사용되는 helper 함수들 → 사용처에 인라인 또는 제거

---

### Deprecated Props 제거

**무엇을**: 하위 호환성을 위해 남겨둔 옛날 props/API

**왜 불필요한가**:

- **학습 목적**:
    - 학습용으로는 최신 방식 하나만 이해하면 충분
    - 옛날 API를 배울 이유 없음
- **혼란**: "어느 걸 써야 하나?" → 선택지 줄이기

**삭제 대상**:
- deprecated 표시된 props
- 옛날 API를 새로운 API로 변환하는 병합 코드

---

### 메타데이터 제거

**무엇을**: 개발/디버깅/문서화를 위한 추가 정보

**왜 불필요한가**:

- **학습 목적**:
    - PropTypes는 타입 검증 도구이지 핵심 로직이 아님
    - TypeScript를 사용하면 빌드 타임에 검증 (더 강력)
    - displayName은 DevTools에서만 유용
- **프로덕션**: PropTypes는 빌드 시 제거됨

**삭제 대상**:
- `PropTypes` - 런타임 타입 검증
- `displayName` - 디버깅용
- `defaultProps` - 함수 파라미터 기본값으로 대체

---

### SSR 마운트 안전성 패턴 제거

**무엇을**: SSR(서버사이드 렌더링) 환경에서 hydration 오류를 방지하는 mounted 상태 패턴

**왜 불필요한가**:

- **학습 목적**:
    - 클라이언트 전용 학습 환경에서 SSR 대응 코드는 불필요
    - 핵심 로직을 가리는 부가 코드
- **현실**: Next.js 등 SSR 프레임워크 없이는 의미 없음

**삭제 대상**:
- `const [mounted, setMounted] = useState(false)`
- `useLayoutEffect(() => setMounted(true), [])`
- `mounted && ...` 조건부 렌더링 → 직접 렌더링으로 대체
