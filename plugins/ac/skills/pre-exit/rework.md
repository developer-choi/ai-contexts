# 재작업이 있었던 세션

이번 세션에 재작업·재지시가 있었을 때 여는 파일.

## 사용자 측 원인

재작업의 원인이 사용자 요청 측에 있었는지 본다 — 기술스택·코드구조 전제가 요청에 안 담겼거나, 요구가 다의적이었거나, 한 번에 과한 분량을 맡겼거나.

해당하면 어느 쪽이었는지 사용자에게 짚어 보고한다. 사용자 자기 회고용이라 규칙화하지 않는다.

## 앞 단계 결손

한 산출물을 다시 만들었으면, 그 재작업을 없애려면 앞 단계 산출물에 무엇이 갖춰졌어야 했는지 본다.
문제가 난 자리에 규칙을 심으면 같은 실수의 재발까지만 막고, 앞 단계에 없던 재료는 생기지 않는다.
없는 결손을 지어내지는 않는다 — 앞 단계마다 안 쓰일 규칙이 붙는다.

갖춰졌어야 했던 것은 특정 스킬·절 이름 없이 적는다 — 구조가 바뀌어도 다음 구조에서 다시 쓰인다.
