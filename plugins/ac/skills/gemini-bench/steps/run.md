# 실행

양쪽 모두 벤치를 설계한 세션이 아닌 새 세션에서 실행한다. Gemini가 직접 실행하는 쪽은 Antigravity CLI(`agy`)를 사용한다.

## 격리는 지시가 아니라 환경으로 만든다

지시만으로는 Gemini가 실제 레포를 바꾸는 것을 막지 못한다. 실행 환경은 피실험 모델이 실제 레포에 닿을 수 없게 만든다. 도구를 사용하지 못하는 ask-llm 회차는 해당하지 않는다.

- Gemini 쪽에는 대상 레포를 클론하고 remote를 뗀 폴더, 또는 히스토리 없는 새 레포를 준다. git 워크트리는 격리가 아니다. `agy`는 워크트리의 본체 레포를 작업 폴더로 되잡는다
- `agy`는 명령을 실행한 폴더가 아니라 `--add-dir`로 준 폴더를 작업 폴더로 사용한다. 작업 폴더를 주지 않으면 홈 폴더 전체에서 스킬을 찾는다
- 두 쪽의 산출물과 임시 파일이 섞이지 않게 쪽마다 폴더를 가른다. 같은 경로에 저장하면 나중에 실행한 쪽이 앞 것을 덮는다. 스킬이 OS 임시 폴더에 고정된 이름으로 저장하면 세션마다 `TEMP`·`TMP`를 다른 폴더로 준다

## 회차마다 로그로 확인한다

- 상대가 실제로 받은 입력을 세션 로그로 확인한다. 입력이 일부만 전달돼도 응답은 그럴듯하게 나와서, 산출물만 보면 입력을 못 받은 것인지 받고도 안 따른 것인지 알 수 없다. `agy` 대화 기록은 `~/.gemini/antigravity-cli/conversations/`에 SQLite로 있다
- 격리됐는지는 산출물이 아니라 로그에 남은 작업 폴더로 확인한다
- 끝난 뒤 실제 레포의 `git status`가 비어 있는지 본다
