# Gemini에 넘겨도 되나

Claude 사용 한도를 절약하려고, 어떤 작업을 Gemini에 넘겨도 되는지 같은 과제를 양쪽에 실행해 판단한다.

지난 벤치의 기록(무엇을 측정했고 무엇이 나왔는지)은 backlog 레포(`~/WebstormProjects/main/backlog`)의 `archives/research/gemini-bench/`(이하 벤치 기록 폴더)에 있다.

## 설계

앞선 측정은 벤치 기록 폴더의 벤치 목록(`overview.md`의 파일 안내가 가리킨다)에서 찾는다. 목록의 "N차"는 벤치 전체에 매기는 일련번호라, [재벤치](../SKILL.md#재벤치-언제-다시-돌리고-언제-멈추나)의 회차는 같은 대상을 고쳐 다시 측정한 횟수로 따로 센다.

### 무엇을 비교할지 정한다

- **넘길지 판단할 때**: 일부를 Gemini에 맡기도록 고친 스킬과 고치기 전 스킬을 처음부터 끝까지 각각 실행해 비교한다
- **후보를 좁힐 때**: 넘길 부분만 떼어 양쪽 모델에 직접 실행한다. 도구 없이 답만 받는 일이면 Gemini 쪽은 [ask-llm](../../../contexts/ask-llm.md)으로 보낼 수 있다

### 양쪽이 같은 입력을 받게 한다

두 모델의 결과 차이가 입력 차이에서 나오지 않게 한다.

## 실행

Gemini가 직접 실행하는 쪽은 Antigravity CLI(`agy`)를 사용한다.

### 격리는 지시가 아니라 환경으로 만든다

지시만으로는 Gemini가 실제 레포를 바꾸는 것을 막지 못한다. 실행 환경은 피실험 모델이 실제 레포에 닿을 수 없게 만든다. 도구를 사용하지 못하는 ask-llm 회차는 해당하지 않는다.

- Gemini 쪽에는 대상 레포를 클론하고 remote를 뗀 폴더, 또는 히스토리 없는 새 레포를 준다. 대상 레포에 벤치 기록 폴더가 들어 있으면(backlog) 클론은 히스토리로 정답을 넘기니, 기록 폴더를 뺀 히스토리 없는 새 레포를 준다. git 워크트리는 격리가 아니다. `agy`는 워크트리의 본체 레포를 작업 폴더로 되잡는다
- `agy`는 명령을 실행한 폴더가 아니라 `--add-dir`로 준 폴더를 작업 폴더로 사용한다. 작업 폴더를 주지 않으면 홈 폴더 전체에서 스킬을 찾는다
- 두 쪽의 산출물과 임시 파일이 섞이지 않게 쪽마다 폴더를 가른다. 같은 경로에 저장하면 나중에 실행한 쪽이 앞 것을 덮는다. 스킬이 OS 임시 폴더에 고정된 이름으로 저장하면 세션마다 `TEMP`·`TMP`를 다른 폴더로 준다
- 격리됐는지는 산출물이 아니라 로그에 남은 작업 폴더로 확인한다

## 측정

넘긴 일이 일어나는 구간을 사용자 입력 단위로 선택해 두 버전에 같은 구간을 적용하고, [session-usage](../scripts/session-usage.md)로 Claude 토큰(`total`)과 걸린 시간을 측정한다. Gemini가 직접 실행한 회차의 시간은 이 스크립트로 측정할 수 없으니, 그 회차는 양쪽을 같은 기준으로 측정한다.

회차 편차를 가늠할 수 있게, 넘긴 일이 없는 구간도 함께 측정한다.

## 채점

정답이 1차 소스로 정해지는 과제는 정답과 대조하고, 정답이 하나로 정해지지 않는 품질 비교(의역·해설 등)는 블라인드 A/B로 채점한다.

### 블라인드 A/B

사용자가 어느 모델의 산출물인지 모른 채 문항마다 판정하게 한다. 페이지는 [blind-ab](../scripts/blind-ab.md)로 만들고 `node "${CLAUDE_SKILL_DIR}/../../contexts/local-html-roundtrip.mjs" open blind-ab <blind.html 경로>`로 연다.

- 한쪽에만 붙어 출처를 알려 주는 것(메인이 붙인 메모, 모델 이름)은 양쪽에서 지운다
- 말투(존댓말·평서체)만으로도 모델을 짐작할 수 있다. 판정 뒤 짐작됐는지 사용자에게 묻고, 짐작됐으면 블라인드가 지켜지지 않았다고 벤치 기록에 남긴다

### 정답 대조

원본으로 확인한 것만 틀렸다고 판정한다. 결론과 URL이 맞아도 인용은 원문과 다를 수 있다.

### 채점자 실수를 모델 탓으로 돌리지 않는다

모델 능력에서 나온 결함만 감점한다. 이번 입력이 시험하지 않는 항목이나, 채점하기 쉽게 벤치가 덧붙인 제약을 어긴 것은 모델 능력과 무관하다.
